# v5 상품 인식 구조 — 목표와 방향

결정일: **2026-10-25 KST**, 사용자 승인. 제출 마감: 사용자 제공 **2026-10-29**.

이 문서가 v5의 목표·인식 구조·등록 상태 판정의 기준이다. 2026-10-26 아래 구조의 코드·씬·데이터 변경과 EditMode 97/97 검증을 완료했다. 후속 요청으로 `0.5.0 (5)` APK를 빌드하고 기존 앱 삭제 후 Galaxy A25에 새 설치했다. 카메라 영상·참조 이미지 3개 로딩·SessionTracking은 확인했으며 실물 제품 인식은 미검증이다. [새 설치 결과](validation/product-recognition-v5-device-2026-10-26.json). 바코드로 먼저 상품을 고르고 앞면을 기다리던 v4 흐름은 [강의 기반 이미지 추적 상품정보판](PRODUCT-IMAGE-TRACKING.md)에 남아 있다. 강의 원문 대조는 [강의 검토·완성 계획](COURSE-ALIGNED-PLAN.md)을 따른다.

## 1. 목표

두 층의 목표를 구분한다.

| 층 | 목표 | 역할 |
|---|---|---|
| **최종 서비스** | 바코드로 **PriceTrace 등록 제품인지 판별**하고, 미등록 제품은 등록 대상으로 알린다 | 바코드가 등록 여부 판정의 기준 |
| **이번 과제** | 강의 요구를 지키고 강의 방법을 직접 활용한다 | 상품 **앞면 이미지 추적**을 적극 활용해 정보를 실물의 위치·방향에 결합 |

앞면 이미지 경로와 바코드 경로는 **서로를 기다리지 않고 각자 단독으로 상품 정보를 출력한다.** 시연과 보고서에서는 앞면 3D 경로를 먼저, 가장 길게 보여준다. 바코드 판별은 강의 밖 확장이자 실제 서비스 목표로 배치한다.

## 2. 인식 경로와 표시 방식

```
카메라 프레임 ─┬─ ARTrackedImageManager ─ 참조 이미지 이름 ─┐
               │  (Chap4)                                     ├─ 상품 ID ─ 로컬 카탈로그
               └─ 바코드 디코더 (EAN-13, 3회 확인) ─ EAN ──────┘   (가격·영양)
```

| 경로 | 얻는 정보 | 표시 |
|---|---|---|
| 앞면 이미지 FULL_TRACKING | 상품 ID + **3D 위치·방향** | 박스 표면에 붙는 World Space 정보판, 영양/가격 탭 |
| 바코드 확인 | 상품 ID 또는 미등록 번호 + **화면 2D 위치만** | 화면 추종 2D 정보판 |

- 바코드는 3D 자세를 주지 않는다. 같은 상품 정보라도 바코드 경로에서 3D 정보판을 띄우지 않는다.
- 바코드로 찾은 상품에 앞면 이미지가 있으면 **"앞면 이미지 등록됨 · 앞면을 비추면 3D로 표시"** 배지를 붙인다. 출력을 막는 안내가 아니다.
- 앞면과 바코드가 같은 상품을 가리키며 동시에 보이면 3D 정보판을 우선한다.

## 3. 등록 상태 4종

등록되지 않은 앞면 이미지는 ARCore가 찾지 못하므로 **"모르는 앞면"이라는 사건은 발생하지 않는다.** 따라서 4종은 스캔 결과가 아니라 **상품별 데이터 등록 상태**로 정의하고, 미등록 판정은 바코드로만 한다.

| 상태 | 앞면 스캔 | 바코드 스캔 | 의미 |
|---|---|---|---|
| ① 앞면·바코드 모두 등록 | 3D 정보판 | 2D 정보판 + "앞면 등록됨" 배지 | 정상 |
| ② 앞면만 등록 | 3D 정보판 + **"바코드 미연결"** | 모르는 번호 → ④와 같은 안내 | 카탈로그에 상품은 있으나 바코드 매핑 누락 |
| ③ 바코드만 등록 | 인식 없음 | 2D 정보판 + "앞면 미등록" | 정상. 앞면은 선택 사항 |
| ④ 모두 미등록 | 인식 없음 | **"등록이 필요한 제품"** + 읽은 번호 | PriceTrace 등록 요청 대상 |

②의 상품 바코드를 찍으면 앱은 그 번호가 같은 상품의 것인지 알 수 없다. ②와 ④를 바코드 쪽에서 구분하지 않으며, ②는 앞면 정보판의 "바코드 미연결" 표시로 드러낸다. 실제로 운영 DB의 기존 바코드 매핑은 확인하지 못한 상태다([과거 기록](M0-M3-validation.md)).

## 4. 판정 규칙

1. **미등록 판정은 확정된 번호로만 한다.** EAN-13 체크섬과 같은 번호 3회 연속 확인을 통과해야 한다. 오판독 한 번으로 "등록 필요"를 띄우지 않는다.
2. **판정 기준 시점을 표시한다.** 현재 카탈로그는 로컬 JSON 스냅샷이다. 화면 문구는 "PriceTrace 미등록"이 아니라 **"로컬 카탈로그(스냅샷 날짜) 기준 미등록"**으로 쓴다. 실시간 조회는 후속 과제다.
3. **3D 표시는 FULL_TRACKING일 때만 한다.** 제한·소실·LAST_KNOWN_POSE·pause에서는 숨기고 선택 상태를 해제해 새 상품을 인식할 수 있게 한다. 바코드는 최신 판독 실패·다른 번호가 도착하면 이전 확정을 해제한다. 입력 자체가 멈추면 마지막 입력의 0.65초 뒤 만료한다. 미등록 번호 안내도 같은 소실 규칙을 따른다.
4. **현재 충돌은 숨긴다.** 앞면 A를 추적하는 중 다른 상품 B의 바코드가 확정되면 3D 정보판을 숨기고 경고한다. 서로 다른 상품의 앞면이 동시에 추적될 때도 같다. 충돌 대상이 사라지면 수동 재스캔 없이 현재 보이는 상품의 인식을 재개한다.
5. **영양/가격 탭은 상품이 바뀔 때만 초기화한다.** 같은 상품의 추적 복구에서는 유지한다.

## 5. 데이터 모델

v4의 `product-images.json`은 **바코드를 키**로 쓰고 바코드 중복을 거부한다. 이 구조로는 ②(바코드 없는 상품)와 한 상품의 여러 앞면을 표현할 수 없다. v5는 **상품 ID를 기준 키**로 한다.

```
상품 (catalogProductId)
 ├─ 바코드        0~1개   → 바코드 경로 조회
 └─ 앞면 이미지   0~N장   → 이미지 이름 → 상품 ID 조회
```

- `demo-products.json`은 이미 `catalogProductId`를 갖는다. 바코드를 필수에서 선택으로 바꾼다.
- 앞면 연결 파일은 `referenceImageName → catalogProductId`로 바꾼다. 이미지 이름은 전체에서 유일해야 하고, 같은 상품에 여러 이미지를 허용한다.
- 기존 검증은 유지한다: 라이브러리에 없는 이미지, 중복 이미지 이름, 카탈로그에 없는 상품 ID, 상품 포장 이미지의 실측 Physical Size 누락은 초기화 오류다.
- 카드 `test-card`는 `developmentOnly`로 남겨 개발용 연결임을 계속 표시한다.

## 7. 앞면 참조 이미지 준비

첫 대상은 **Dr.Elizabeth's 테아닌과 밀크씨슬 활력솔루션** 박스(종이 상자, 앞면 평면)다. 강의 ZIP의 `arcoreimg eval-img` 결과(2026-10-25, 권장 75점 이상):

| 사진 | 앞면 전체 | 위쪽 절반 | 아래쪽 절반 |
|---|---|---|---|
| `iphone-t1.jpg` | 15 | 95 | 100 |
| `galaxy-t1.jpg` (vFlat) | 0 | 85 | 100 |
| `phone-t1.jpg` | 0 | 100 | 100 |

- 앞면 전체는 1:2 비율과 넓은 단색 영역 때문에 점수가 낮은 것으로 추정한다. 원인을 분리 검증하지는 않았다. 흑백 변환·축소는 개선이 없었다.
- **위·아래 절반 크롭 2장**을 같은 상품의 앞면 이미지로 등록한다. 박스 일부가 가려져도 남은 쪽으로 추적한다. 같은 상품의 복수 참조 영역을 지원하며, 각 영역 중심의 오프셋을 공통 상품 원점으로 보정한다. Vuforia MultiTarget 자체를 구현하거나 사용한 것은 아니다.
- Physical Size는 박스 앞면 **가로 폭 실측값**을 쓴다. 크롭해도 가로 폭은 같다.
- 점수는 실물 추적 성공을 보장하지 않는다. 큐브로 먼저 실물 박스의 인식·이동·회전·가림·재획득을 확인한다.
- 원본 사진과 크롭 내역을 보관하고 보고서의 도구 활용 내역에 vFlat 사용을 적는다.

## 10. 시작 전 필요한 입력

- 테아닌 밀크씨슬 박스의 EAN-13 번호.
- 박스 앞면 가로 실측값(mm).
- 가격·성분 표시 데이터와 출처. 건강기능식품이므로 영양 탭은 1일 섭취량·기능성 원료 중심이 될 수 있다. 출처가 없는 값은 누락으로 표시한다.
- ④ 시연용 미등록 바코드 상품 1개.

## 11. 2026-10-26 구현 결과와 데이터 경계

아래는 최초 v5 구현 시점의 기록이다. 이후 `0.5.1 (6)` 빌드·호환 업데이트와 소실 복구 수정은 [후속 검증](validation/v5-rescan-panel-fix-2026-10-26.json)을 따른다. 커밋 전 재검증은 [105/105 시험 결과](validation/branch-delivery-2026-10-26.json)에 기록했다. 외부 상품 검색·PT 실시간 연결은 [도입 보고서](BARCODE-PRODUCT-LOOKUP-RESEARCH.md)의 제안 범위다.

- `ProductCatalog`는 상품 ID 조회·선택적 바코드·필수 스냅샷 날짜를 지원한다. 이미지 연결은 스키마 v2의 `referenceImageName → catalogProductId`다. 이미지가 0개인 카탈로그도 유효하며 등록 상태 4종은 자동 시험용 데이터로 각각 확인했다.
- `ProductImageState`는 바코드 선택 없이 현재 이미지를 상품에 연결한다. 같은 상품의 여러 크롭은 허용하고 서로 다른 상품의 동시 추적은 충돌로 판정한다.
- `ProductRecognitionState`가 별도 프레임·체크섬·3회 확인, 오래된 판독 거부, 3D/2D 우선순위와 충돌을 소유한다. `ProductARApp`은 관측·판정 후 두 정보판의 표시를 조율한다. 스캐너는 연속 관측 모드에서 초기 시간 제한 없이 동작한다.
- `iphone-t1`의 정확한 상·하단 반분 두 장(95/100점)을 사용했다. 두 크롭이 같은 원본이므로 상대 위치를 정의할 수 있다. 사용자 제공 `iphone-t2` 100점은 대안으로 보존했다. 준비 근거는 [이미지 입력 기록](validation/v5-image-inputs-2026-10-26.json)이다.
- 사용자 실측은 **약 5.8cm**다. 두 영역의 폭을 0.058m로 설정하고 반분 높이에서 계산한 크롭별 Z 오프셋을 추가했다. 원본의 촬영 원근·경계 오차와 근사 실측이 있으므로 실물 크기·전환 정합은 미검증이다.
