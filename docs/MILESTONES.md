## 목표와 범위

같은 AR 카메라의 EAN-13으로 상품을 선택하고 등록 이미지의 3D 자세에 정보판을 표시한다. 앞면 전환 중 바코드가 안 보여도 선택을 유지한다. 영양/가격 탭과 재스캔을 제공한다. 먼저 상품 1종의 완결된 실물 흐름을 확보한다.

현재 브이젤 카드와 더단백 데이터의 연결은 개발용이다. 카드의 실물 큐브 추적 성공을 실제 상품 포장이나 새 정보판의 통합 성공으로 판정하지 않는다.

이번 구현·문서 작업에서는 **앱 빌드·APK 생성·설치·실물 시험을 수행하지 않았다.** 기존 APK를 새 기능의 결과로 사용하지 않는다.

## 구현된 표시 규칙

- 선택은 바코드로만 확정한다. 미등록 번호·이미지의 임의 상품 fallback은 없다.
- 일치 이미지의 FULL_TRACKING과 카메라·세션 준비 조건이 있어야 표시한다.
- 이미지 소실·제한·마지막 자세·다른 이미지에서는 숨기고, 일치 이미지만 다시 추적되면 복구한다.
- 다른 유효한 EAN을 읽으면 원래 선택을 유지한 채 숨기며 명시적 재스캔을 요구한다.
- pause·재스캔 후 새 카메라 프레임과 이미지 갱신을 기다린다.
- 추적 복구에서는 탭을 유지하고, 재스캔·새 상품 바인딩에서는 영양 탭으로 초기화한다.
- 상품 포장 마커에는 실측 Physical Size를 요구한다. 개발용 카드의 크기는 추정값이다.
- 기존 평면 탐색·Raycast·앵커와 2D 바코드 표시기는 현재 기본 모드에서 비활성화한다.

## 다음 작업과 완료 조건

1. **실제 포장 등록:** 촬영 원본과 vFlat 후보를 보관하고 같은 영역의 품질을 비교한다. 사진과 동일한 실물 영역의 너비·높이를 측정한다. 점수만으로 성공을 확정하지 않는다.
2. **새 통합의 실물 검증:** 적절한 시점에 별도 빌드·설치한 뒤 [DEVICE-CHECKLIST.md](DEVICE-CHECKLIST.md)로 확인한다. 현재 작업에서 실행한 것으로 기록하지 않는다.
3. **정량 확인:** 동일 조건에서 10회 중 8회 이상 5초 내 식별/표시, 잘못된 상품 표시 0회를 개발 목표로 삼는다. 강의 공식 루브릭이나 현재 달성 수치가 아니다. 실패·조건·기기·소스·APK를 함께 기록한다.
4. **제출물:** 실물 결과에 맞춰 보고서를 수정하고 1~2분 무음성 영상, 이름·학번을 넣은 템플릿 문서, 파일명·압축·원본 보관을 확인한다.

2번째 상품은 1종의 검증·영상 확보 후 여유가 있을 때 추가한다. OpenCV/PnP, 실행 중 마커 등록, Vuforia 전환, 실시간 가격·로그인·구매는 이번 우선 범위에서 제외한다.
