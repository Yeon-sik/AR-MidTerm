# B: 실물 라면 3종 등록안

2026-10-28 `feat/ui-p0-video`의 등록 전 검토안이다. **원격 적용 전 / 사용자 승인 대기**이며, 현재 검증된 PT 바코드는 기존 더단백·테아닌 2종이다. 아래 세 상품을 새로 등록하면 앱 시연 대상은 5종이 된다. [정확한 값·예정 ID·사진 해시](data/b-three-products-2026-10-28.json)와 [로컬 사전 검증](validation/b-three-products-preflight-2026-10-28.json)을 함께 확인한다.

사용자가 촬영한 포장 사진 4장의 바코드·중량·영양표를 대조했다. 진라면은 최초 제공명과 동일 바코드의 **약간매운맛 봉지 120g**이다. 기존 PT의 매운맛 용기 110g, 순한맛과 연결하지 않는다. The미식은 영양표와 바코드를 찍은 두 장을 대조했다. 사진 원본은 Git 제외 `artifacts/v0.7.0/b-labels/`에 보존한다.

아래 값은 모두 **포장 총 내용량당**이다. 100g당·조리 후 값으로 바꾸지 않는다.

세 상품의 트랜스지방·콜레스테롤은 표기된 0을 보존한다. 표시되지 않은 식이섬유·첨가당은 null로 남긴다. 칼슘은 원문 검토 데이터에 보존하지만 현재 앱의 영양 표시 항목에는 추가하지 않는다. 출처는 **사용자 제공 포장 영양표 → Fitness Nutrition 수동 검토 공개 자료**다. OFF의 영양 자료로 기록하지 않는다.

사용자는 구매 가격·판매처·구매일을 모두 모른다고 답했다. 가격·구매·관측 행을 생성하지 않으며 화면은 ‘가격 정보 없음’이 정상이다. 제조사 페이지는 브랜드·제품군의 보조 근거이고, 사진으로 확인한 단품 바코드나 가격의 대체 근거가 아니다. 제조사 묶음 상품 가격도 가져오지 않는다.

## 원격 변경 범위

| 시스템 | 생성할 자료 | 기존 자료 처리 |
|---|---|---|
| PriceTrace | The미식 브랜드 1개, 표준 상품 3개, 1봉 카탈로그 3개, 검증 EAN 연결 3개 | 기존 오뚜기 브랜드·면 카테고리 사용. 기존 상품·가격·구매 기록 수정 없음 |
| Fitness Nutrition | 포장 기준 영양 3개, 정확 PT 상품 연결 3개, 공개 처리 3건 | 기존 공개 PT 시연 영양의 관리 계정에 새 자료를 귀속. 기존 음식·영양 자료 수정 없음 |

예정 ID는 신규로 생성한 식별자이며 아직 운영 등록 ID가 아니다. 영양 소유 계정은 기존 공개 PT 시연 자료에서 확인하며, 계정 식별자·접속 키는 공개 문서나 앱에 기록하지 않는다. 새 영양 3건을 승인 연결 후 기존 공개 함수로 발행한다. 스키마·RLS·권한은 변경하지 않는다.

사용자 요청에 따라 [The미식 브랜드 공식 자료](THE-MISHIK-BRAND-RESEARCH.md)를 조사했다. **The미식(더미식)은 하림산업이 운영하는 식품 브랜드**다. 신규 브랜드 대표명은 The미식으로 유지하고, 공식 사이트를 `https://the-mishik.com/`으로 정정한다. 운영사는 조사 메타데이터에 별도로 기록하며 기업 소속만으로 다른 브랜드의 부모 ID를 만들지 않는다. 브랜드 확인 요청은 원격 등록·공개 승인이 아니므로 계속 승인 대기다.

## 적용 순서와 검증

1. 이 등록안과 **영양 공개**를 포함한 사용자 승인을 받는다.
2. 원격의 동일 EAN·예정 ID·브랜드 충돌 여부를 다시 읽는다. 다른 상품에 연결돼 있으면 중단한다.
3. PriceTrace에서 3개 상품·EAN 연결을 하나의 트랜잭션으로 생성한다.
4. 운영 `get_product_read_v1`에서 새 상품 3개의 정확 ID·규격·revision을 다시 받는다. 로컬 시험의 revision은 사용하지 않는다.
5. Fitness Nutrition에서 해당 운영 문서와 포장 영양을 대조하여 새 자료를 생성·연결·공개한다.
6. 익명 공개 PT 바코드·영양 조회를 검사한다. 세 상품의 가격은 null이어야 한다.
7. 승인·적용된 ID와 영양으로 앱 스냅샷을 갱신하고 회귀 시험·릴리스 빌드·A25 `-r` 업데이트를 한다. 세 바코드와 영양·가격 없음 표시를 실물 확인한다.

두 서버의 변경은 하나의 분산 트랜잭션이 아니다. 영양 단계가 실패하면 PT 상품은 존재하고 영양은 미공개일 수 있으므로 상태를 기록하고 같은 ID로 재시도한다. 기존 자료 삭제나 자동 역변경은 하지 않는다. 철회가 필요하면 이번에 만든 영양의 공개 해제·새 상품 비활성화를 별도로 검토한다.

준비 SQL은 Git 제외 `artifacts/v0.7.0/b-three-products-pt.apply.sql`과 `b-three-products-nutrition.apply.sql`이다. 정확한 배치 승인 값이 없으면 중단하며, 영양 SQL은 새 운영 상품 문서 3개도 요구한다. 파일 SHA-256은 사전 검증 JSON에 고정했다.

## 확인 수준과 남은 작업

실제 서버에서 테이블 제약·공개 읽기·발행 함수 정의를 **읽기 전용**으로 확보하여 별도의 로컬 PGlite DB 두 개에서 등록안을 시험했다. **41/41 통과**: 바코드·규격·누락값·사진 해시, 승인 누락 거부, 다른 상품 EAN 충돌 거부, 잘못된 110g 연결 거부, 공개 읽기·영양값, 재실행 중복 방지를 포함한다. 인증 역할·해시 함수는 로컬 시험 대역이며 운영 트리거·RLS를 복제하지 않았다. 운영 등록·익명 HTTP·A25 화면 성공을 증명하는 결과가 아니다.

앱의 최신 Unity 시험 **378/378**은 소스 `ab7687e`의 기존 기록이다. 이번 등록안 준비에서는 Unity 코드·APK를 변경하지 않았고 시험 수도 합산하지 않는다. 원격 적용, 새 스냅샷 빌드, 세 상품의 기기 확인은 **미수행**이다.

세 상품을 PT에 등록하면 정상 조회는 PT 경로가 된다. A의 **OFF 영양 발견 실물 시연**은 별도 식품이 필요하며 아직 완료하지 않았다. 오른쪽 12mm·15° 배치, 인식·충돌·소실 규칙, 포장 주석 제외는 이번 등록 범위에서 유지한다.
