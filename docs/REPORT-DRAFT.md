## 1. 콘텐츠 기획의도

### 배경과 조사 근거

**[AI 초안]** 상품을 고를 때 상품명·규격과 영양 기준량을 함께 확인해야 한다. 본 프로젝트는 검색어를 입력하는 대신 바코드로 정확한 상품을 선택하고, 관련 정보를 해당 실물의 위치·방향에 연결해 보여주는 방법을 구현한다.

질병관리청 수도권질병대응센터의 「수도권역 만성질환 통계 알리미」 제2권 제6호(2026-04-23)는 **2024년 가공식품 선택 시 영양표시 이용률을 40.2%**로 제시한다. 이 지표는 **초등학생 이상이 가공식품을 고를 때 영양표시를 읽는 분율**이며, 연도별 추이는 표준화율이다. 이 수치는 영양정보 확인이 실제 소비 행동이라는 배경 근거로 사용한다. 미이용의 원인이 작은 글씨라거나 AR로 이용률이 향상된다는 인과관계는 이 통계로 입증하지 않는다. [질병관리청 원문, 본문 8쪽·작성 기준](https://www.kdca.go.kr/bbs/capital/153/307583/download.do)

기존 기술 사례로 Open Food Facts의 공식 튜토리얼은 상품 바코드를 읽은 뒤 상품명·영양 관련 값을 조회하는 과정을 설명한다. 따라서 바코드 기반 식품정보 조회는 공개 구현 사례를 가진 접근이다. 본 프로젝트는 조회 결과를 실물의 3D 자세에 결합하는 상호작용을 목표로 한다. Open Food Facts API를 현재 앱에 연동했다는 뜻은 아니며, 앱은 출처가 기록된 로컬 시연 데이터를 사용한다. [Open Food Facts 공식 튜토리얼](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorial-off-api/)

### 필요성

**[AI 초안]** 같은 이름의 상품도 맛·용량·묶음 단위가 다르면 정보가 달라질 수 있어 정확한 식별이 필요하다. 사용자가 들고 있는 실물과 표시된 정보의 대응도 유지해야 한다. 이를 위해 바코드는 상품 선택에, 미리 등록한 포장 이미지는 표시 위치·방향 결정에 사용한다. 가격은 특정 판매처·날짜의 관측값으로 표현하고, 영양정보는 기준량과 단위를 함께 표시한다.

### 증강현실 활용 목적

**[AI 초안]** AR을 사용하는 목적은 정보가 어느 실물에 속하는지를 공간적으로 보여주는 것이다. 목표 흐름은 바코드를 읽고 포장 앞면으로 돌린 뒤에도 선택을 유지하고, 추적된 앞면의 위치·방향에 정보판을 붙이는 것이다. 휴대폰의 각도와 거리를 바꾸어도 정보판이 같은 이미지의 자세를 따르는 장면을 시연한다. 이 공간 대응의 편의성·이해도 개선은 아직 사용자 비교 실험으로 측정하지 않았다.

| 강의의 AR 요소 | 현재 구현 | 검증 범위 |
|---|---|---|
| 현실·가상 결합 | AR 카메라와 World Space 정보판 | 씬·코드 연결 확인, 새 통합 화면 기기 검증 대기 |
| 실시간 상호작용 | 이미지 자세 갱신, 영양/가격 탭, 재스캔 | 상태·좌표·버튼 이벤트 자동 시험 통과, 기기 터치 대기 |
| 3차원 공간에 놓임 | 추적 이미지 Transform의 위치·회전에 정보판을 정합 | 3D 계산 자동 시험 통과. 과거 카드 위 큐브의 실물 추적 성공과 새 정보판 통합 검증을 구분 |

사전 이미지 등록은 강의 Chap4의 Reference Image Library·Physical Size·ARTrackedImageManager 과정을 적용한 것이다. 바코드 자체의 3D 자세를 계산하는 방식은 이번 구현에 포함하지 않는다.

## 2. 콘텐츠 목표

### 대상 사용자

**[AI 초안]** 간식의 단백질·당류 등 영양정보와 가격 관측을 실물 옆에서 확인하려는 Android 사용자다. 시연 데이터는 빙그레 더단백 크런치바 초코 40g 1종이다. ARCore 지원 휴대폰과 판독·이미지 추적에 적절한 조명을 전제로 한다.

### 목표 경험

- 바코드로 상품과 정확한 규격을 선택한다.
- 포장 앞면으로 돌릴 때 바코드가 사라져도 선택한 상품을 유지한다.
- 등록 이미지의 3D 위치·방향을 따라가는 정보판에서 영양/가격을 전환한다.
- 가격의 판매처·관측일·출처와 영양 기준량을 확인한다.
- 추적이 끊기거나 다른 상품이 보이면 잘못된 정보가 남지 않도록 숨기고 재시도한다.

**현재 제약:** 실제 상품 포장 참조 이미지와 실측 크기는 아직 준비하지 않았다. 현재는 브이젤 카드 마커와 더단백 데이터의 **개발용 연결**이며, 화면에도 상품 포장 인식이 아님을 표시한다.

## 3. 핵심 구현 내용

### 3-1. 기능과 강의 적용

**[AI 구현]** 카메라 실행 → 동일 EAN-13 3회 확인 → 로컬 상품 선택 → 연결 이미지 추적 → 3D 정보판 → 영양/가격 탭 → 다른 상품 스캔 흐름을 구현했다.

| 기능 | 주요 코드·에셋 | 동작 |
|---|---|---|
| 카메라·AR 준비 | ARReadiness, ARBarcodeScanner | 같은 AR 카메라에서 EAN 판독, 권한·세션·pause/복귀 처리 |
| 정확한 상품 선택 | BarcodeConfirmation, ProductCatalog, ProductWorkflow | 서로 다른 프레임의 3회 일치, 시연 데이터에 없는 번호는 대체 상품으로 연결하지 않음 |
| 상품↔이미지 연결 | ProductImageCatalog, product-images.json | 바코드와 Reference Image Library 이름 연결, 중복·오타·미등록 거부, 상품 포장에는 실측 크기 요구 |
| 이미지 추적 표시 | ProductImageState, TrackedImageProductPanel, ImageTrackingPolicy | 일치 이미지의 FULL_TRACKING만 표시. 소실·제한·마지막 자세·다른 이미지에서 숨김 |
| 3D 정합 | ProductImageLibrary, World Space Canvas | 매 LateUpdate에 이미지의 위치·방향 반영. 표면 오프셋과 이미지 폭에 비례한 정보판 크기 |
| 정보판 상호작용 | WorldProductPanel, ProductInfoPanel.prefab | 영양/가격 탭과 재스캔, 관측일·출처, 누락값/0 구분 |
| 상태 안내 | ProductARApp, ProductScreenView | 바코드 스캔→이미지 추적의 2단계, 다른 상품·추적·권한·데이터 문제 안내 |
| 코드 검증 | ProductImageTests, Test-EditMode.ps1 | 이미지 표시 정책, 실제 앱 이벤트 연결, 3D 계산, 데이터·버튼 기능 검사 |

바코드가 사라졌다는 이유로 정보판을 만료시키지 않는다. 다른 유효한 바코드가 읽히면 기존 선택을 바꾸지 않고 숨기며, 명시적 재스캔을 요구한다. 이미지 추적이 소실되면 숨기고 일치 이미지만 재획득하면 복구한다. pause·재스캔 후에는 새 카메라 프레임과 이미지 갱신을 기다린다.

| 강의 원문 | 적용 |
|---|---|
| Chap3-Theory (2), 4·9쪽 | 마커의 위치·방향 기준 합성, AR 3요소를 기능·검증으로 구분 |
| Chap4-Practice (2), 21쪽 | Reference Image Library·Physical Size·ARTrackedImageManager |
| Chap4-Practice (2), 27~30쪽 | 이미지 품질 평가와 실측 준비. 품질 점수만으로 실물 성공 판정하지 않음 |
| Unity UI 버튼 실습 | 영양/가격 전환과 재스캔의 클릭 이벤트 |
| 강의 밖 보완 | ZXing.Net EAN 판독과 기존 ARCore FULL_TRACKING 상태 확인 코드 재사용 |

새 SDK·OpenCV/PnP·동적 마커 등록은 추가하지 않았다. 기본 이미지 추적 모드에서는 평면 탐색·Raycast·공간 앵커와 이전 2D 표시기를 비활성화한다.

### 3-2. 구현한 부분과 검증 수준

**[AI 구현]** Unity 6000.3.22f1에서 **EditMode 76/76 통과**, 실패·건너뜀 0, 에디터 종료 코드 0이다. 기존 회귀 51개와 새 이미지 정보판 기능 25개를 포함한다.

- 바코드 선택 유지, 이미지 소실·재획득, 다른 이미지·다른 번호 거부.
- 참조 이미지 등록·실측 크기·JSON 연결 검증.
- 실제 ProductARApp의 상품 선택→정보판→재스캔 이벤트 연결.
- 3D 위치·방향·크기 계산과 pause/복귀 시 이전 자세 무효화.
- 영양/가격의 정상·일부 누락·0·전체 누락 바인딩, 버튼 포인터 영역과 이벤트 전달.

World Space 버튼 검사는 카메라·GraphicRaycaster 연결, 실제 UI API의 포인터 영역과 ExecuteEvents 전달을 확인했다. 렌더링된 Graphic.depth의 히트 정렬이나 휴대폰 터치를 검증한 것은 아니다. RuntimeOnly 리스너는 시험 인스턴스에서만 EditMode 실행 조건을 맞췄다. 원본 프리팹 설정은 유지한다.

**[사용자 확인]** 과거 기기 성과는 다음과 같다.

| 대상 | 확인한 결과 | 현재 통합과의 관계 |
|---|---|---|
| 이전 상품 앱 | Galaxy A25에서 실물 EAN과 정확한 상품명 표시 | 식별 경로의 선행 근거. 새 통합 흐름 반복 시험은 아님 |
| 이전 평면 배치 | 휴대폰 이동 중 같은 책상 위치 유지 | v2 성과이며 현재 기본 모드는 비활성 |
| 카드 이미지 probe | 실물 브이젤 카드의 FULL_TRACKING, 카메라 회전·거리 변화 중 큐브 유지 | 이미지 추적의 선행 근거. 새 상품정보판의 기기 성공을 대신하지 않음 |

**이번 통합에서는 앱 빌드·APK 생성·설치·실물 시험을 수행하지 않았다.** 기존 APK는 변경되지 않았다. 현재 카드의 실측 크기도 미확정이며 추정 크기를 사용한다.

### 3-3. 남은 작업과 발전 방향

제출 전에는 실제 상품 포장의 원본/vFlat 후보 평가, 선택한 영역의 실측 Physical Size, 상품 통합 기기 시험, 1~2분 무음 시연 영상과 최종 Word 보고서가 필요하다. 이름·학번과 실제 기기 결과는 제출자가 확인한다. [실물 시험 절차](DEVICE-CHECKLIST.md), [마일스톤](MILESTONES.md)을 따른다.

후속 확장은 상품 추가, 관측값 갱신과 비교 기능이다. 바코드 경계·실측·카메라 파라미터를 사용한 PnP나 실행 중 이미지 등록은 장기 연구 항목으로 둔다. 바코드 화면 좌표의 Raycast가 상품 표면을 보장한다고 가정하거나, 움직인 상품을 마지막 앵커 위치로 표시하는 방안은 채택하지 않는다. [기술 조사](BARCODE-MARKER-RESEARCH.md)

로그인·구매·실시간 가격 수집·AI 상품 분류는 구현 범위 밖이다. 바코드 매핑은 demo-only이며 운영 DB 연결 검증과 구분한다. 1,400원은 국군복지단 바다마을마트의 2026-05-08 관측값이며 현재 판매가가 아니다. 영양정보는 40g 기준이고 포장 표기 직접 대조는 남아 있다.

**[AI 초안]** 기존 보고서 초안에는 Claude, 구현·검증과 이번 최신화에는 Codex를 사용했다. 사용자 제공 사진을 생성형 AI로 재작성하지 않았다. 이번 문서 작업은 실제 포장 사진의 vFlat 보정·등록을 수행한 기록도 아니다. 외부 템플릿·ZXing.Net·Noto Sans CJK KR 라이선스는 저장소에 보존한다.

## 5. 데모 영상 계획과 제출

아래는 **촬영 계획**이며 현재 영상은 없다. 실제 상품 마커 통합 검증 이후 실행 화면으로 1~2분, 음성 설명 없이 촬영한다. 개발용 카드를 촬영하면 카드 검증임을 자막에 표시하고 상품 포장 성공으로 설명하지 않는다.

|---|---|
| 0:00~0:15 | 실행, 상품 바코드와 정확한 상품 선택 |
| 0:15~0:30 | 포장 앞면으로 전환, 바코드 소실 중 선택 유지 |

제출물은 템플릿 보고서와 실행 영상이며 프로젝트 원본을 보관한다. 파일명·압축·업로드는 이클래스 공지와 대조한다. 사용자 제공 마감일은 10월 29일이고 마감 시각은 확인하지 않았다.
