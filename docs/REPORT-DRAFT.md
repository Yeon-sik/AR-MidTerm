## 1. 콘텐츠 기획의도

### 배경

**[사람]** 마트나 편의점에서 상품을 들고 가격과 영양성분을 비교하려면 포장 뒷면의 작은 표를 읽거나, 휴대폰으로 상품명을 검색한 뒤 결과 중 정확한 규격을 다시 골라야 한다. 같은 이름이라도 용량·맛·묶음 단위가 다르면 정보가 달라진다. 예를 들어 첫 시연 상품인 빙그레 더단백 크런치바 초코는 40g 1개 기준으로 영양정보가 정해져 있다.

⟪입력: 템플릿이 요구하는 조사 근거. 예: 식품 영양표시 확인 실태 조사, 장보기 중 모바일 검색 이용 통계, 기존 바코드 앱 사례. 출처와 연도를 함께 적는다. AI가 수치를 만들어 넣지 않았다.⟫

### 필요성

**[AI 초안]** 문제를 겪는 사람은 상품을 손에 든 채 정보를 확인하려는 소비자다. 기존 방식에는 다음 한계가 있다.

- **포장 표 읽기**: 글자가 작고 항목 배열이 제품마다 다르다. 가격 정보는 포장에 없다.
- **상품명 검색**: 이름을 입력하고 결과 중 정확한 규격을 골라야 한다. 비슷한 상품을 잘못 고르면 다른 상품의 정보를 보게 된다.
- **일반 바코드 앱**: 번호로 상품을 정확히 찾지만, 결과가 실물과 분리된 별도 화면에 나타난다. 사용자는 실물과 화면을 번갈아 보며 같은 상품인지 스스로 대조해야 한다.

### 증강현실 활용 목적

**[AI 초안]** 이 콘텐츠의 AR은 "정보가 어느 실물의 것인지"를 화면 위치로 보여주는 데 쓰인다.

1. **실물 위에 정보를 겹친다.** 바코드를 비추면 터치 없이 그 바코드 바로 위에 정보창이 나타난다. 사용자는 시선을 옮기지 않고 지금 들고 있는 상품의 정보임을 확인한다. 실물과 결과 화면이 분리된 일반 바코드 앱과 다른 점이다.
2. **움직이는 실물을 따라간다.** 상품을 손으로 움직이면 바코드가 보이는 동안 정보창도 따라 움직인다. 바코드가 가려지거나 다른 상품의 바코드가 보이면 정보창을 즉시 숨겨, 정보가 엉뚱한 상품 위에 남지 않게 한다.
3. **포장에 이미 인쇄된 바코드를 마커로 쓴다.** 강의의 마커 기반 AR(Chap3-Theory 4쪽)은 QR코드·로고·이미지 같은 마커의 위치를 기준으로 가상 정보를 합성한다. 이 콘텐츠는 별도 마커를 붙이지 않고, 거의 모든 포장에 있는 EAN-13 바코드를 식별자이자 위치 기준으로 사용한다.

**Azuma의 증강현실 3요소(Chap3-Theory 9쪽)와의 대응**

| 요소 | 충족 여부 | 근거 |
|---|---|---|
| 현실과 가상 영상의 결합 | 충족 | AR 카메라 영상 위에 상품정보창을 합성 |
| 실시간 상호작용 | 충족 | 약 4Hz 이하로 바코드를 다시 읽어 위치를 갱신하고, 가림·다른 번호에 즉시 반응 |
| 3차원 공간 안에 놓임 | **부분 충족** | 바코드의 **화면 2D 위치**에 정합한다. 깊이·방향(Pose)은 추정하지 않는다 |

**[사람]** 3번째 요소는 의도적으로 절충했다. 이전 v2에서는 책상 평면에 ARAnchor로 정보판을 고정했고, Galaxy A25에서 휴대폰을 움직여도 같은 위치에 유지되는 것을 확인했다. 그러나 상품을 옮기면 정보판이 빈 책상에 남아 재배치가 필요했다. 2026-10-24 제출자가 "바코드 위에 나타나고 상품을 움직이면 따라다니는 방식"을 선택했다. 손에 든 상품과의 대응이 이 콘텐츠의 핵심이라고 판단했기 때문이다.

**[AI 초안]** 강의의 분류로는 휴대기기 기반의 Weak AR(Chap3-Theory 37쪽)에 해당한다. 실물의 3차원 자세까지 추적하는 Strong AR로의 확장은 3-2절 "앞으로 발전할 부분"에 적었다.

## 2. 콘텐츠 목표

### 대상 사용자

**[사람]** 마트·편의점·집에서 상품을 손에 들고 가격과 영양성분을 확인하려는 소비자. 예를 들어 단백질 함량이나 당류를 비교하며 간식을 고르는 사용자다. ARCore를 지원하는 Android 휴대폰과 바코드를 읽을 수 있는 실내 조명을 전제로 한다. 이번 중간 시연은 제출자가 상품 1종으로 진행한다.

### 콘텐츠 목표

**[AI 초안]** 사용 후 사용자는 다음을 할 수 있다.

- **안다**: 손에 든 상품의 정확한 이름·규격과 기준량(40g) 대비 열량·나트륨·탄수화물·당류·지방·포화지방·단백질을 안다.
- **안다**: 가격이 "현재가"가 아니라 특정 판매처·날짜의 관측값임을 안다(1,400원, 국군복지단 바다마을마트, 2026-05-08 관측).
- **할 수 있다**: 검색어 입력이나 화면 터치 없이 바코드를 비추는 것만으로 정보를 확인하고, "다른 상품 스캔"으로 다음 상품으로 넘어간다.
- **느낀다**: 정보가 실물 위에 붙어 움직이므로, 어느 상품의 정보인지 헷갈리지 않는다.

# Part B. 후속 AI 구현자용 메모

**2026-10-25 후속 결정:** 아래의 "v3 그대로" 결정 이후, 제출자가 **이미지 추적 최소 구현 후 실기기 업데이트**를 요청했다. 현재 후속 작업은 [이미지 추적 검증](IMAGE-TRACKING-PROBE.md)의 마커 1개·큐브 1개로 제한한다. Part A는 기존 v3 기록이며 새 추적의 실기기 결과를 반영하기 전 제출본으로 확정하지 않는다. B-3의 A안은 Raycast 히트가 상품 표면이라는 보장이 없으므로 확정 권장안으로 사용하지 않는다. 이미지 추적에서도 데이터·정보판·권한·빌드 도구는 재사용할 수 있다.

**후속 검증·조사:** 카드 APK의 51/51 자동 시험·빌드·Galaxy A25 설치와 실물 FULL_TRACKING을 확인했고, 사용자가 카메라 회전·거리 변화 중 카드 위 큐브 유지를 확인했다. 추가 물리 마커 없이 기존 EAN을 사용하는 기술과 과제 적합성은 [바코드 마커 조사 보고서](BARCODE-MARKER-RESEARCH.md)에 정리했다. 바코드 3D 추적·정보판 통합은 아직 구현하지 않았다.

Part A를 제출 문서로 옮기기 전이나 구현 방향을 바꾸기 전에 이 절을 읽는다.

## B-1. 강의 요구사항과 현재 구현의 차이

## B-2. 설치 제약의 후속 상태와 남은 검증

- **이미지 추적 검증 앱 설치는 해결됐다.** 기본 스크립트의 서명 불일치 중단 후, 사용자의 교체 설치 요청에 따라 백업·교체·데이터 복원을 수행했다. 복원된 IL2CPP 실행 캐시의 소유권 문제도 보존·재생성으로 해결했다. 상세 근거는 [검증 기록](VALIDATION.md)을 따른다. 기본 스크립트의 임의 삭제 방지 동작은 유지한다.
- 이 결과는 카드 이미지 검증 씬의 실행·추적 결과다. 기존 v3의 바코드 좌표 변환(`ArFrame_transformCoordinates2d`)이나 바코드 위 정보창의 실기기 완료 기준을 대신하지 않는다.

## B-3. 방향을 바꿀 때의 선택지

아래 표는 과거 검토안이다. 새로운 바코드 자체의 자세 추정·동적 이미지 등록 대안과 조건은 [조사 보고서](BARCODE-MARKER-RESEARCH.md)를 우선 참고한다. 어떤 방식도 구현·실기기 검증 전에는 3D 정합 완료로 표시하지 않는다.

| 안 | 내용 | 3D 정합 | 재사용 | 위험 |
|---|---|---|---|---|
| A. 하이브리드 (과거 제안) | 바코드 화면 위치로 Plane·FeaturePoint Raycast 후 World Space 정보판 표시 | 상품 표면 히트 검증 필요 | 앵커·평면 처리와 기존 정보판 | 책상 히트는 움직이는 상품의 위치가 아님. 가림 뒤 고정 앵커도 상품 이동을 증명하지 못함 |
| B. v3 + 깊이 | 바코드 지점의 깊이로 3D 위치 계산 | 지원·품질 검증 필요 | v3 전체 | 공식 기기 목록에 Galaxy A25 Depth 지원 표시가 없어 기본 전제로 삼기 어려움 |
| C. 이미지 추적 | 포장 앞면 등 참조 이미지를 추적 | 카드 검증 범위에서 기본 자세 추적 확인 | 권한·데이터·정보판과 새 이미지 추적 코드 | 예전 상품 사진은 품질 0~45점. 브이젤 카드 85점의 성공이 모든 포장 인식을 보장하지 않음 |

A안을 구현한다면:

1. `ProductARApp.OnObserved`에서 v3 화면 패널과 앵커 배치를 함께 처리할지, 화면 패널을 대체할지 먼저 정한다. 화면 패널은 "실물 위 즉시 표시"라는 장점이 있으므로 기본은 병행을 권한다.
2. 앵커를 매 관측마다 새로 만들지 말고 일정 거리 이상 차이가 날 때만 교체한다. 이전 앵커는 제거한다.
3. 씬은 `ProjectBuilder`가 생성한다. 씬을 직접 고친 뒤 **Product AR → Prepare Project and Scene**을 실행하면 수정이 덮어써진다.
4. 바꾼 뒤 Part A의 1-3절 대응표("부분 충족" → "충족"), 3-1절 표, 3-2절, 5절 영상 구성안, B-1 표를 고친다.

## B-4. 바꾸지 말아야 할 약속

- 바코드 연결은 `demo-only`다. 운영 DB 매핑이 검증된 것처럼 쓰지 않는다.
- 가격은 2026-05-08 관측값이다. "현재가", "최저가"로 표현하지 않는다.
- 영양값의 누락(null)과 0을 구분한다. 데이터에 없는 일일 기준치 비율을 추가하지 않는다.
- 다른 바코드를 읽으면 선택 상품을 자동으로 바꾸지 않는다. 오연결이 누락보다 나쁘다.
- 에디터 시험이나 빌드 성공을 실기기 성공으로 기록하지 않는다. 실행하지 않은 시험을 PASS로 쓰지 않는다.
- 상품 사진과 바코드 이미지를 AI로 만들거나 고치지 않는다.
