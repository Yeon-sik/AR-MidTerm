# 바코드 위 자동 정보창 — 기획 v3

**과거 구현 기록:** 2026-10-25 이후 기본 흐름은 [이미지 추적 정보판](PRODUCT-IMAGE-TRACKING.md)이다. 아래 2D 바코드 추종과 0.65초 소실 규칙은 현재 이미지 정보판의 동작 기준이 아니다.

확정일: **2026-10-24 KST**. 사용자가 “바코드 위에 나타나고, 상품을 움직이면 따라다니기”를 선택했던 v3 화면의 기록이다. 기존 평면 터치 배치 중심의 v2 목표·시험도 과거 기록으로 보존한다. 정확한 상품 ID·관측 가격·영양 기준량·demo-only 데이터 의미는 현재도 유지한다.

## 사용 흐름

1. 같은 AR 카메라에서 EAN-13을 서로 다른 프레임 3회로 확인한다.
2. 정확한 로컬 상품을 조회하면 터치 없이 바코드 부근에 상품정보창 하나를 표시한다.
3. 선택한 바코드를 최대 약 4Hz로 계속 판독해 화면 위치를 갱신한다. 실제 갱신 주기는 카메라·디코더 처리 시간에 따라 낮아질 수 있다.
4. 정보창은 바코드 위에 놓고, 위쪽 공간이 부족하면 아래로 옮긴다. 안전 영역·상태·버튼과 겹치지 않도록 제한하며, 바코드를 가리지 않고 넣을 공간이 없으면 숨긴다.
5. 마지막 유효 영상의 촬영 시점부터 0.65초가 지나면 정보창을 숨긴다. 다른 번호를 읽으면 즉시 숨기고 선택 상품을 자동 변경하지 않는다. 같은 번호가 다시 보이면 자동 표시한다.
6. 다른 상품 스캔은 선택 상품·위치·이전 비동기 결과를 정리한다. 앱 pause에서도 위치를 지우고 복귀 후 같은 바코드를 다시 읽어 표시한다.

카메라에서 보이는 **바코드의 2D 위치를 따라가는 화면 UI**다. 바코드가 포장 뒤로 가려진 뒤에도 상품 전체를 추적하는 3D 객체 인식은 포함하지 않는다. 현실 책상에 앵커를 두거나 공간 위치를 유지하는 기능과 구분한다. 기존 `ProductPlacement`와 평면 감지는 기본 실행 씬에서 비활성화한다.

## 코드와 좌표

- `BarcodeDecoder`: ZXing EAN 판독 선분 두 점을 원본 CPU 영상 좌상단 기준 정규화 좌표로 반환한다. `BarcodeReaderGeneric.AutoRotate` 대신 EAN 판독기 내부 회전 처리를 사용해 결과점이 원본 입력에 대응하도록 한다.
- `ARCoreBarcodeCoordinates`: Unity ARCore의 문서화된 version 1 세션·프레임 포인터에서 카메라 콜백 중 `ArFrame_transformCoordinates2d(IMAGE_NORMALIZED → VIEW_NORMALIZED)`를 호출한다. 회전·잘림을 포함한 변환값만 보존하고 네이티브 포인터를 작업 스레드로 넘기지 않는다. 패키지에 포함된 ARM64 `libarcore_sdk_c.so`에서 함수 export를 확인했다.
- `ARBarcodeScanner`: 초기 식별과 선택 상품 추종을 분리한다. 추종에는 초기 15초 제한을 적용하지 않는다. 디코더는 동시에 하나만 실행하며 촬영 시각·화면 크기·변환을 함께 보존한다. 재시작 이전 세대 결과는 무시한다.
- `BarcodeFollowState`: 선택 번호만 허용한다. 지연된 결과·변환 없음·화면 잘림 밖 위치는 표시하지 않는다. 임의 화면 중앙이나 임의 3D 거리를 사용하지 않는다.
- `BarcodeProductPanel`: 상품명·규격과 별도 관측 가격 영역, 영양성분표를 표시한다. 가격은 금액·판매처·관측일·개당 기준을 분리하고, 영양성분표는 기준량·열량과 나트륨/탄수화물/당류/지방/포화지방/단백질을 항목·함량 열로 정렬한다. 제공되지 않은 일일 기준치 비율은 추가하지 않으며 누락값과 0을 구분한다. 시연용 연결·로컬 데이터 문구를 유지한다.
- `ProductARApp`: 스캔과 추종 2단계 상태, 위치 준비·소실·권한·데이터 오류, 다른 상품 스캔을 연결한다.

API 근거: [ARCore 좌표 변환](https://developers.google.com/ar/reference/c/group/ar-frame#arframe_transformcoordinates2d), [Unity ARCore 네이티브 세션](https://docs.unity3d.com/Packages/com.unity.xr.arcore@6.3/manual/features/session.html), 패키지 `Includes~/UnityXRNativePtrs.h`, [ZXing 0.16.11 회전·결과점 처리](https://github.com/micjahn/ZXing.Net/blob/v0.16.11.0/Source/lib/oned/OneDReader.cs).

## 실기기 완료 기준

- 실제 상품을 10회 보여줘 터치 없이 올바른 정보가 나타나는지 기록한다. 정상 실내에서 10회 중 8회 이상 5초 내 식별·오연결 0회를 목표로 한다.
- 상품을 화면 좌·우·상·하로 천천히 움직여 바코드와 정보창의 위치 대응, 세로 화면 잘림, 가독성을 확인한다. 에디터 좌표·UI 시험으로 기기 정합 성공을 대신하지 않는다.
- 가림·화면 이탈·다른 번호·재스캔·Home 복귀 후 이전 위치가 잘못 남지 않는지 확인한다.
- 네트워크 없이 동작하고 5분 연속 추종에서 부하·발열·오류·자원 증가를 기록한다. 스캔 후에도 판독이 계속되므로 기존 정지형 정보판의 시험으로 대체하지 않는다.
- Android의 실제 네이티브 호출은 `CPU image → viewport mapping ready` 로그와 화면으로 확인한다. 빌드·심볼 존재만으로 기기 성공을 판정하지 않는다.

현재 결과와 APK는 [검증 기록](VALIDATION.md)을 따른다.
