## C 현장 등록의 구현과 한계

PT `matched` 또는 OFF 상품 발견으로 이름·식별자가 확인된 2D 상품 화면에서 ‘앞면 등록’을 누른다. 중앙 가이드에 앞면을 맞춰 촬영하면 이미지 검증 후 기존 사전 등록 이미지를 유지하는 런타임 라이브러리에 추가한다. 검증 실패 시 다른 무늬·반사가 적은 면을 촬영하도록 안내한다. 취소·일시정지·늦게 완료된 이전 등록이 현재 상품을 바꾸지 않도록 처리한다.

등록 버튼을 누른 시점의 표시 상품과 출처를 메모리에 복사한다. 이후 앞면 추적은 그 복사본을 사용하며, PT ID가 없는 OFF 상품은 정확한 바코드로 구분한다. 온라인 DTO를 로컬 `Selected`에 넣지 않는다. OFF 상품의 출처와 PT 바코드 연결 필요 상태는 3D에서도 보존하고, 없는 가격·영양을 만들지 않는다. 현재 시험 앱의 진라면은 OFF에 이름만 있어 영양을 표시하지 않았다. 이후 확보한 포장 영양은 아래 B 등록안의 별도 Fitness Nutrition 자료이며, 아직 원격 공개하지 않았다.

등록 이미지·연결 정보는 **이번 앱 실행에서만 유지**하며 파일이나 서버에 저장하지 않는다. 앱 프로세스를 완전히 종료하면 사라진다. 실측 크기를 입력하지 않아 ARCore의 추정 크기를 사용하며, 오른쪽 12mm·15° 배치는 유지하되 실제 상품 경계와의 정합은 사전 등록 상품보다 덜 정확할 수 있다. 무늬가 적거나 반사가 심한 포장은 거절될 수 있다. 재스캔은 등록 목록의 영구 저장 기능이 아니다.

표면은 평평하고 구겨지지 않아야 한다. 내용물이 든 봉지의 굴곡이나 촬영 후 변하는 주름은 인식을 어렵게 할 수 있다. 등록 이미지의 특징 검증 통과와 실물 재인식 성공을 구분한다. [ARCore 요구 조건](https://developers.google.com/ar/develop/augmented-images#requirements). 0.7.0 (14)의 진라면은 native 추가·상품 연결 성공 뒤 사용자가 인식 실패를 보고했으며, 원인은 미확정이다. 15번 빌드의 재시험 로그는 최초 FULL_TRACKING·Image3D와 Limited 시 해제·FULL_TRACKING 시 복귀를 확인했다. 최초 추적까지 약 13초이며 추가 갤러리 사진에서 진라면 정보판·윤곽·연결선과 상품·출처 문구 전체를 확인했다. 사용자도 완전 가림 시 모두 숨김·복구됨을 확인했다. 최종 영상은 카드 배경·윤곽이 화면 끝에 걸리지 않도록 더 넓게 촬영한다.

개발용 `0.7.0-probe.2`에서는 2026-10-28 13:37 KST에 등록 성공 → 최초 FULL_TRACKING → 소실 → 재획득 로그와 사용자 성공 확인을 확보했다. [프로브 검증 JSON](validation/runtime-registration-probe-2026-10-28.json)과 `artifacts/v0.7.0/registration-probe-2/reacquisition.log`가 근거다. 추정 크기 0.1297×0.207m는 실측값이 아니며, 프로브 성공은 정식 앱의 상품 정보판 성공을 증명하지 않는다.

## 조회·표시 규칙

EAN-13을 서로 다른 프레임에서 3회 확인한 뒤 PT 공개 바코드 함수를 조회한다. 로컬 스냅샷이 있으면 먼저 표시하되 온라인 확인 상태와 스냅샷 날짜를 구분한다.

| 결과 | 다음 조회와 표시 |
|---|---|
| PT `matched` | 정확한 PT 상품 ID로 승인 공개 영양 조회. PT 등록 상태, 상품·규격, 존재하는 관측가·영양 표시 |
| PT `not_linked` | OFF v3 조회. 발견하면 상품·영양·OFF 출처와 PT 바코드 연결 필요 표시 |
| OFF 정상 미발견 | 읽은 번호와 상품정보 미발견 안내 |
| PT 오류·오프라인·계약 불일치 | PT 등록 여부 확인 불가. 가능한 로컬 스냅샷과 날짜 표시. OFF로 우회하지 않음 |
| PT `conflict` / `invalid` | 자동 상품 선택·영양 조회·OFF 우회 없이 연결 또는 번호 확인 안내 |

PT의 정상 미연결 상태명은 `not_linked`다. 이는 공개 가능한 바코드 연결을 찾지 못했다는 뜻이며 PT에 해당 상품 자체가 없다는 증거는 아니다. 상품명 유사도로 ID를 연결하지 않는다.

기존 3회 확인·늦은 응답 무시·소실 시 해제·다른 상품 동시 관측 시 숨김·pause/재스캔 초기화 규칙을 유지한다. 온라인 DTO는 로컬 `Selected`에 주입하지 않는다. 실제 표시 상품과 키를 버튼·상품 전환의 기준으로 사용한다.

## 영양과 가격의 출처

PT 영양은 `nutrition-read.v1` 공개 함수에서 정확 PT ID로 받은 자료다. 다른 ID 응답이나 복수 영양 행을 임의로 선택하지 않는다. 결과가 없으면 영양 없음으로 남긴다.

OFF 영양은 판매 상태의 `*_100g` 표준 필드를 사용한다. 액체는 원문의 단위 근거에 따라 100ml로 표시하며, 단위가 없거나 상충하면 질량과 부피를 임의 변환하지 않는다. 포장당 값·1회분 값·조리 후 값을 섞지 않는다. kcal가 없으면 명시된 kJ를 4.184로 나누며 나트륨 g는 mg로 환산한다. 소금값만으로 나트륨을 생성하지 않는다. 잘못된 수치·누락값은 비워 두고 실제 0은 표시한다. 출처는 Open Food Facts이며 유효한 자료 수정 시각이 있으면 갱신일을 함께 표시한다. 이 날짜는 가격 관측일이 아니다.

가격은 관측가만 표시한다. PriceTrace의 확정 계약 `docs/contracts/PUBLIC_BARCODE_LOOKUP_V1.md`를 확인했다(`feat/public-barcode-lookup`, 확인 소스 `13750c8`). 해당 v1은 `latestPublicPrice.kind=listed`만 발행하며 `observed`는 향후 공개 구매 관측 경로를 위한 예약 값이다. 앱은 게시가를 관측가로 바꾸어 표시하지 않는다.

현재 두 시연 상품은 서버 가격이 null이므로, 화면에 표시하는 금액은 내장 PT 관측 스냅샷이다. 추가 바코드를 연결해도 서버 관측가·승인 영양이 자동으로 생기지는 않는다. OFF는 이 앱의 가격 공급원이 아니며 가격 없음은 정상 상태다. 관측가는 관측일·판매처의 기록으로 현재가나 최저가를 보증하지 않는다.

사용자는 진라면·스낵면·The미식 3종으로 진행하도록 요청하고 포장 사진 4장을 제공했다. 단품 EAN·중량·영양표를 대조하여 **진라면 약간매운맛 120g (`8801045014869`)**, **스낵면 108g (`8801045520728`)**, **The미식 메밀비빔면 121g (`8809778493005`)**의 신규 상품 등록안을 준비했다. 구매 가격·판매처·구매일은 모두 알 수 없어 관측가를 만들지 않는다.

[등록안](B-THREE-PRODUCTS-PLAN.md)은 The미식 브랜드 1개, PT 표준·카탈로그·EAN 각 3개와 Fitness Nutrition 영양·정확 상품 연결 각 3개의 생성·공개 범위를 명시한다. 영양은 각 포장 전체 기준이며 OFF에서 가져온 값이 아니다. 기존 공개 PT 시연 영양의 관리 계정을 사용하며 기존 음식·가격·구매 자료를 변경하지 않는다. 원격 적용 전 로컬 사전 검사 **41/41 통과**와 운영·기기 미수행을 [별도 JSON](validation/b-three-products-preflight-2026-10-28.json)에 기록했다. **원격 등록·영양 공개는 사용자 승인 대기**다. 아직 현재 연결 수 2종을 5종으로 보고하지 않는다.

## 반복 가능한 서버 검사

`scripts/Test-ProductLookup.ps1`은 PowerShell 7 이상에서 실행한다. 읽기 전용 공개 PT 바코드·영양 RPC와 OFF GET만 호출하며 등록·수정 기능이 없다.

```powershell
./scripts/Test-ProductLookup.ps1 -Barcodes '8809375984692','8801104671507'
./scripts/Test-ProductLookup.ps1 -Barcode '3017624010701' `
  -OutputPath artifacts/v0.7.0/off-check.json
```

로컬 설정의 기본 위치는 `Assets/Config/remote-lookup.local.json`이다. 생성은 `scripts/Initialize-RemoteLookup.ps1`을 사용한다. 설정 파일이 없는 앱은 로컬 전용으로 동작하며, 이 진단 스크립트는 설정을 읽을 수 없으면 네트워크 요청 전에 중단한다. 키·설정 URL·연락처·원문 응답·예외 메시지는 진단 결과에 기록하지 않는다.

출력의 `pt`는 서버 상태·상품·규격·가격, `nutrition`은 승인 공개 영양 상태·기준량·값, `off`는 OFF 결과, `localSnapshot`은 내장 자료다. `pt.price=null`과 `localSnapshot.price`가 동시에 존재할 수 있으며 두 값을 합쳐 서버 응답으로 보고하면 안 된다. OFF 진단의 `nutrition.values`는 표준 필드의 원문 수치여서 나트륨 g→mg 같은 앱 화면 변환 전 값이다. 오류는 unavailable, 계약 위반은 contract_error, 정상 미발견은 not_found로 구분한다.
