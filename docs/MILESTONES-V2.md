# 바코드 기반 상품정보 AR — 기획 및 마일스톤

**v2 보관본:** 2026-10-25 최신화 전에 사용하던 평면 터치 배치 계획과 당시 v3 안내를 보존한다. 현재 작업 범위는 [MILESTONES.md](MILESTONES.md), 현재 실물 절차는 [DEVICE-CHECKLIST.md](DEVICE-CHECKLIST.md)다. 아래 체크·성과를 새 이미지 정보판의 완료 상태로 해석하지 않는다.

**2026-10-24 기획 v3 변경:** 사용자가 바코드 인식 직후 자동 표시·상품 이동 시 따라다니기를 선택했다. 기본 상호작용과 새 완료 기준은 [바코드 자동 정보창](BARCODE-FOLLOW.md)을 따른다. 아래 v2는 기존 평면 터치 배치의 범위·성과·시험 기록이며 현재 화면 동작의 기준으로 사용하지 않는다. 상품 매핑·관측 가격·영양 기준량 의미는 유지한다.

기획 버전: **v2 / 2026-10-23 KST**. 사용자 확정: **바코드 인식 후 상품 옆을 터치해 현실 공간에 정보판을 배치한다.**

이 문서가 현재 기획·범위·단계 통과 조건의 기준이다. 이미지 추적 중심의 이전 단계 번호와 통과 조건은 [구기획 검증 기록](M0-M3-validation.md)으로 보존한다. 2026-10-23 사용자가 가능한 범위까지 자율 구현하고, 사용자 개입이 필요한 검증을 기다리는 동안 독립적인 후속 구현을 계속하도록 지시했다. 따라서 M0~M7의 구현 가능한 작업을 진행하되, 실기기·실물 검증이 미완료인 단계는 PASS로 올리지 않는다. 현재 결과는 [구현·검증 기록](VALIDATION.md)과 [바코드 해상도 분석 기록](BARCODE-RESOLUTION.md)을 따른다.

## 1. 목표와 사용 흐름

대상 사용자는 제품을 앞에 두고 가격·영양정보를 확인하려는 사람이다. 키보드 검색 대신 제품의 바코드로 정확한 상품을 식별하고, 사용자가 지정한 상품 옆 공간에 관련 정보를 배치한다.

1. AR 카메라를 실행하고 바코드를 스캔한다.
2. 읽은 바코드와 정확한 상품 ID의 매핑을 확인한다.
3. 로컬 스냅샷에서 상품명·브랜드·규격, 가격 관측, 영양정보를 읽는다.
4. “상품 옆에 정보를 배치할 위치를 눌러주세요.”라고 안내한다.
5. 사용자가 감지된 현실 평면을 터치하면 그 위치에 정보판 하나를 배치한다.
6. 카메라를 움직여도 정보판이 지정한 공간에 유지되는 것을 확인한다. 재배치·삭제·다시 스캔을 제공한다.

바코드는 **상품 식별**, 평면 Raycast는 **배치 위치 결정**, AR 공간 추적은 **배치 위치 유지**를 담당한다. 바코드만으로 상품의 3차원 위치·방향을 얻었다고 가정하지 않는다. 정보판은 상품을 자동으로 따라가지 않는다. 상품을 옮기면 사용자가 재배치한다.

## 2. 동결된 MVP 범위

### 포함

- Android 실기기에서 AR Session·카메라 실행.
- 동일 AR 카메라의 CPU 이미지를 이용한 바코드 판독.
- 첫 시연 상품 1개: **빙그레 더단백 크런치바 초코 40g**.
- 바코드 문자열 → `catalogProductId`의 명시적 매핑.
- 검증한 로컬 JSON의 가격·영양정보 사용.
- 수평 평면 감지, 터치 Raycast, 현실 공간에 정보판 1개 배치.
- 정보판 재배치·삭제, 다시 스캔, 추적 중단·정보 없음·스캔 실패 안내.
- 실기기 반복 시험, 기본 성능·리소스 관리, 보고서와 데모 영상.

### 제외

- 상품 표지·부분 이미지 인식, Reference Image Library, `targetName` 기반 식별.
- 참조 이미지 품질 점수, 상품 포장 평면 고정, 인쇄 영역 크기 측정.
- 바코드·상품 위치에 대한 자동 3D 정합, 상품 이동을 따라가는 정보판.
- 여러 상품·정보판 동시 표시, 상품 비교, 복잡한 제스처 조작.
- OCR, YOLO, AI 상품 분류, 외부 상품 자동 검색·등록·추천.
- 로그인, 구매, 실시간 가격 수집, 원격 DB 필수 연결.
- 별도 `WebCamTexture` 세션, Vuforia 전환·병용.

## 4. 최소 구현 구조

```text
ARCameraManager → XRCpuImage → 픽셀 변환 → ZXing.Net → barcode 문자열
                                                           ↓
                                              정확한 로컬 상품 매핑
                                                           ↓
                                              로컬 상품정보 스냅샷
                                                           ↓
터치 → ARRaycastManager → 수평 평면의 Pose → 공간에 정보판 프리팹 배치
```

- Unity **6000.3.22f1 LTS**, AR Foundation·ARCore XR Plugin **6.3.5** 유지. ZXing.Net 0.16.11·Apache-2.0을 도입했고 Android IL2CPP 합성·실물 판독을 확인했다. 실물 10회 반복은 M2의 남은 검증이다.
- AR Session, XR Origin, AR Camera Manager·Background를 사용한다. M3에서 AR Plane Manager·Raycast Manager를 사용한다.
- 배치한 콘텐츠는 검증된 평면 트래커블 또는 앵커를 기준으로 유지한다. 평면이 계속 갱신되는 동안의 고정 방식과 앵커 API는 현재 패키지 문서와 실기기 시험으로 확정한다.
- 단순한 바코드 판독, 배치 제어, 데이터 조회, 표시 책임으로 나눈다. 미래용 추상화나 원격 연동 계층을 미리 늘리지 않는다.
- 스캔 중에만 제한된 빈도로 CPU 이미지를 처리한다. 2~5Hz를 초기 조정 범위로 두며, 최종 빈도는 기기에서 결정한다. `XRCpuImage`와 변환 요청은 사용 후 해제한다.
- UI 버튼 터치는 AR 배치로 처리하지 않는다. Raycast 실패·세션 추적 중단 상태에서 임의 거리로 정보판을 생성하지 않는다.

## 5. 마일스톤과 통과 조건

단계 의존 순서는 **M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7**이다. 사용자 개입이 필요한 검증은 미검증으로 남기고, 그 결과에 의존하지 않는 후속 코드는 구현·로컬 검증한다. 로컬 자동 시험과 실물 시험을 구분하며, 실패한 검증을 문서 작성이나 에디터 성공으로 대신하지 않는다.

아래 수치·시험 횟수는 이 프로젝트의 검증 목표이며 교수자가 지정한 평가 기준은 아니다. 체크리스트의 구현 완료와 단계 전체의 실기기 통과를 구분한다. 2026-10-24 실물 스캔·정확한 상품 조회·수평 평면·앵커 배치를 로그로 확인했고 사용자가 이동 중 같은 위치 유지를 확인했다. M2/M3 정량 반복과 장시간·예외 시험은 남아 있다.

| 단계 | 핵심 결과 | 현재 상태 |
|---|---|---|
| M0 | 환경·기기·시연 Identity 준비 | 준비 완료 / demo-only 근거 |
| M1 | Android AR 카메라 실행 | 기본 실행 확인 / 실제 공간 추적·센서 pause/resume 확인 |
| M2 | 동일 카메라의 바코드 판독 | PARTIAL / 실물 스캔·상품명 표시 사용자 확인, 10회 정량 시험 대기 |
| M3 | 터치 기반 현실 공간 배치 | PARTIAL / 실제 배치·이동 중 위치 유지 확인, 반복·장시간 시험 남음 |
| M4 | 정확한 상품 매핑·로컬 데이터 연결 | 구현·로컬 검증 완료 |

### M0. 환경·기기·시연 상품 준비

**목표:** 사진 준비에 의존하지 않는 실행·데이터 전제를 확보한다.

- [x] 지정 에디터, Android 도구, 패키지 버전을 확인하고 기존 환경 기록과 차이가 있으면 갱신한다.
- [x] 실제 ARCore 지원 Android 기기, OS, USB 연결·디버깅 승인을 확인한다.
- [x] 실물의 상품명·브랜드·40g 규격·바코드 숫자 대조 근거를 기록한다. 사용자 제공 확인과 직접 확인을 구분한다.
- [x] 운영 매핑을 검증하거나, 사용자 확인 근거를 가진 `demo-only` 매핑의 출처·상태를 검증 기록에 확정한다. 운영 DB에 매핑을 생성하거나 조회 권한을 변경하지 않는다.
- [x] 기존 가격·Nutrition 근거와 누락값 의미를 확정한다. 앱용 JSON 작성은 M4에서 수행한다.

**통과:** 실행 기기와 시연용 상품·바코드·데이터의 근거가 준비됨. M2에서 수행할 기기 바코드 판독을 M0에서 선행 요구하지 않는다. 이미지 점수·포장 치수는 통과 조건에서 제거한다.

**산출물:** 환경·기기 기록, 시연 Identity 및 매핑 출처 기록.

- [x] 최소 1분 실행하고 크래시·검은 화면·세션 오류 여부를 기록한다.
- [x] 주변을 비춰 `SessionTracking`과 기기 위치·방향의 정상 추적을 확인한다. 로그와 이동 중 위치 유지에 대한 사용자 확인으로 기록했다.

**통과:** 지정 기기의 설치·권한·카메라·AR SessionTracking·1분 실행을 모두 확인. 에디터만 성공한 경우 통과하지 않는다. 현재 기본 실행과 실제 Tracking은 확인했으며 권한 거부/재허용 전체 경로와 장시간 추적은 별도다.

**산출물:** APK 식별 정보, 빌드 로그, 기기·실행 기록. 기존 설치가 있다면 데이터 보존 여부를 확인하고 호환 업데이트를 우선한다.

### M2. 동일 AR 카메라 기반 바코드 판독

**목표:** 더단백의 실물 바코드를 기존 AR 카메라 영상에서 읽는다.

- [x] ZXing.Net 도입 버전·라이선스와 Unity·Android·IL2CPP 빌드를 확인한다. `System.Drawing`에 의존하지 않는 입력 경로를 사용한다.
- [x] CPU 이미지 획득·변환·회전/미러·메모리 해제를 구현하고 원본 판독값과 형식을 기록한다.
- [x] 바코드는 문자열로 보존한다. 선행 0을 제거하거나 임의로 UPC/EAN 형식을 변환하지 않는다.
- [x] 스캔 시작·중지·재시도를 제공하고 동일 결과가 반복 실행되지 않게 한다.
- [ ] 실물 EAN-13을 10회 판독한다. 매회 상품을 화면에서 뺐다가 다시 보여주고 성공·시간·실패 조건을 기록한다.

**통과 목표:** 기록한 일반 실내 시험 조건에서 10회 중 8회 이상 5초 이내 판독, 판독된 문자열은 매회 기대값과 일치, 오판독 0회, 카메라 충돌·크래시 없음. 실패한 횟수도 기록한다. 최소 1분 동안 스캔 시작·판독·중지·재시도를 반복하고 리소스 고갈·카메라 획득 실패 누적을 확인한다.

**산출물:** 판독 스크립트, 의존성·라이선스 기록, 10회 시험표. 상품정보 UI·일반 상품 Resolver는 아직 구현하지 않는다.

### M3. 터치 기반 현실 평면 배치

**목표:** 상품 옆을 터치해 임시 객체 하나를 실제 공간에 배치·유지한다.

- [x] 수평 평면 감지와 화면 터치 Raycast를 구현한다.
- [x] M2에서 기대 바코드 판독이 확인된 후 배치를 활성화한다. 상품 서비스 대신 검증용 결과를 사용한다.
- [x] 유효한 평면 터치에 작은 Cube 또는 임시 텍스트 프리팹을 하나 배치한다.
- [x] 같은 객체의 재배치·삭제를 제공하고 중복 생성과 남은 앵커를 방지한다.
- [x] UI 터치, 평면 미검출, Raycast 실패에는 배치하지 않는다. 세션·해당 트래커블의 추적이 유효하지 않으면 공간 표시를 숨기고 복구 또는 재배치를 안내한다.
- [ ] 10회 배치·재배치·삭제와, 휴대폰의 좌우 이동·각도 변경을 시험한다.

**통과:** 유효한 Raycast 결과에만 객체 생성, 객체는 화면 고정이 아닌 현실 배치 위치에 유지, 항상 최대 1개, UI 터치 오배치 0회, 삭제 후 잔여 객체 없음. 최소 1분 관찰하며 흔들림·드리프트·소실·복구 조건을 기록한다. 추적 복구 시 잘못된 위치를 숨기지 못하면 미통과다.

**산출물:** 배치 제어·임시 프리팹, 공간 고정·예외 처리 기록, 10회 시험표. **새 기획의 M0~M3 기술 검증은 여기까지**다.

### M4. 정확한 상품 매핑·로컬 데이터 연결

**목표:** 임시 판독 결과를 검증된 상품정보로 연결한다.

- [x] `barcode` → `catalogProductId`의 정확한 매핑과 로컬 JSON 조회를 구현한다.
- [x] 매핑의 `demo-only` 여부·근거, 가격 관측 출처·날짜, Nutrition 기준량·출처를 보존한다.
- [x] 알려진 바코드, 시연 데이터에 없는 유효한 바코드, 데이터 누락을 각각 확인한다.

**통과:** 더단백의 정확한 ID·규격으로 연결되고 숫자·단위·날짜·null이 근거와 일치한다. 시연 JSON에 없는 결과는 **“시연 데이터에 등록된 상품정보가 없습니다.”**로 표시하며 PriceTrace 운영 전체의 미등록으로 단정하지 않는다.

### M5. 상품정보 AR 패널·상태 안내

**목표:** M3의 임시 객체를 상품정보 패널로 교체한다.

- [x] 상품명·브랜드·규격, 관측 가격·판매처·날짜, 기준량을 포함한 영양정보를 표시한다.
- [x] 스캔 중 → 상품 확인 → 평면 탐색/배치 대기 → 배치 완료 흐름을 연결한다. 상품이 확정되면 판독을 중지하고 명시적인 다시 스캔에서만 재개한다.
- [x] 스캔 실패, 시연 매핑 없음, 데이터 일부 누락, 카메라 권한 거부, AR 추적 중단 안내를 제공한다.
- [x] 재배치·삭제·다시 스캔을 연결한다. 삭제 시 선택한 상품은 유지해 다시 배치할 수 있게 하고, 다시 스캔 시 기존 패널·선택 상품을 정리한다.

**통과:** 잘못된 상품이나 이전 스캔의 정보가 표시되지 않고, 정보판은 최대 1개다. 유효한 상품·평면·추적 조건을 갖췄을 때만 공간에 표시한다. 실제 기기에서 글자·단위·버튼을 읽고 조작할 수 있다.

### M6. 통합 실기기 검증·최소 최적화

**목표:** 시작부터 스캔·조회·배치·재시도까지 전체 흐름을 검증한다.

- [ ] 카메라 시작부터 배치 완료까지 10회 반복하고 성공·소요 시간·실패 이유를 기록한다. 정상 조건 8회 이상 완료, 잘못된 상품 연결 0회를 목표로 한다.
- [ ] 미등록 시연 바코드, 손상/읽기 실패, 평면 없음, 추적 소실, 데이터 누락, 앱 백그라운드·복귀를 시험한다.
- [ ] 로컬 스냅샷으로 네트워크 없이 동작하는지 확인한다.
- [ ] 연속 5분 실행해 크래시·지속적인 리소스 증가·반복 스캔 부하·앵커 누적을 확인한다. 실제 기기와 측정 도구·조건을 함께 기록한다.
- [ ] 필요할 때만 스캔하고 데이터는 캐싱한다. 프리팹을 재사용하고 더 이상 사용하지 않는 리소스를 해제한다.

**통과:** 주요 흐름과 예외가 재현 가능한 기록으로 남고 잘못된 상품 표시·추적 중단 중 허위 공간 표시·앱 중단 문제가 해결됨. 성능 측정 없이 FPS·메모리 개선 수치를 주장하지 않는다.

### M7. 보고서·데모 영상·제출 준비

**목표:** 구현 결과와 강의 응용을 실제 실행 근거로 설명한다.

- [x] 강의 보고서 양식의 기획 배경·필요성·AR 목적·대상 사용자·핵심 기능을 작성한다.
- [x] 구현한 부분과 미구현·제한 사항, AI 활용 부분을 구분한다.
- [ ] 바코드 스캔 → 상품 옆 터치 → 공간 고정 → 재배치/삭제를 중심으로 **1~2분 데모 영상**을 제작한다. 강의 제출 안내에 따라 음성 설명을 삽입하지 않는다.
- [ ] 상품이 움직여도 자동으로 따라가는 기능이라고 설명하지 않는다. 시연 스냅샷과 운영 데이터, 에디터와 기기 결과를 구분한다.
- [ ] 보고서·영상 제출 목록과 파일명을 확인하고 프로젝트 원본을 보관한다. 제출 일정은 이클래스 공지를 확인한다.

**통과:** 제출물과 실제 실행 동작이 일치하고, 출처·외부 라이선스·AI 활용·기능 한계가 기록됨.

AR의 역할은 **사용자가 상품 옆에 정한 현실 위치에 정보를 배치하고, 카메라 이동 중에도 그 공간 관계를 유지하는 것**이다. 일반 조회보다 반드시 빠르거나 효율적이라고 주장하지 않는다. 확인한 강의자료에서 이미지 인식의 필수 구현 규정을 찾지 못했다는 판단과 별도 이클래스 공지의 존재 가능성은 구분한다.

## 7. 이전 계획에서 바뀐 점

| 이전 기획 | 확정 기획 v2 |
|---|---|
| 정면 이미지 → `targetName` → 상품 ID | 바코드 → 정확한 상품 ID |
| 이미지 추적 실패 시 바코드 fallback | 바코드를 유일한 상품 식별 경로로 사용 |
| 이미지 Pose를 따라가는 AR 카드 | 사용자가 터치한 평면 위치에 고정되는 정보판 |
| M0에 이미지 품질·실측 포함 | M0에서 환경·기기·상품 Identity·데이터 근거 확인 |
| 구 M2: 이미지 추적 | 새 M2: 바코드 판독 |
| 구 M3: 바코드 판독 | 새 M3: 터치 기반 평면 배치 |
| 첫 상품 이미지 적합성이 전체 진행의 전제 | 이미지 결과는 과거 검증 근거로 보존하고 현재 진행 조건에서 제외 |

구기획의 부분 이미지 후보도 실물 추적 성공이 검증된 것은 아니다. 변경 이유는 **현재 상품의 참조 이미지 준비 비용을 줄이고 강의의 마커리스 배치로 AR 기능을 구성하기 위해서**다. 상품 이미지 인식 전체가 불가능하다고 결론 내린 것이 아니다.

## 8. 기록 규칙과 다음 작업

각 단계 검증 기록에는 날짜·소스 revision/작업 트리·기기/OS·APK·절차·기대 결과·실제 결과·PASS/FAIL/NOT RUN·로그/영상 위치를 남긴다. 새 결과는 `docs/VALIDATION.md`에 기록하고 구기획 기록에 섞지 않는다. 반복 시험은 `시도 번호 / 조건 / 기대 바코드 / 실제 값·형식 / 소요 시간 / 배치 결과 / 실패 이유`를 기록한다. 성공률은 실제 시도 횟수와 함께 계산한다.

원본 강의자료와 사용자 이미지·HTML 등 무관한 입력은 보존한다. 앱 키·조회 원문·APK·생성 캐시는 커밋하지 않는다. 기능 브랜치에서 검토한 경로만 다루고, 설치된 Android 앱이 있으면 삭제나 데이터 초기화 없이 업데이트 가능성을 먼저 확인한다.

**다음 실제 검증:** 기본 실물 스캔→공간 배치→이동 중 고정은 확인했다. 다음은 바코드·배치 10회 정량 기록, 재배치·삭제·추적 복구 및 5분 부하 시험이다. 절차는 [DEVICE-CHECKLIST.md](DEVICE-CHECKLIST.md), 제출 초안은 [REPORT-DRAFT.md](REPORT-DRAFT.md)다.
