# 이미지 추적 상품정보판 — 실물 검증 절차

2026-10-27 최신화. **앞면 AR은 테아닌 1종, 바코드 식별은 더단백·테아닌 2종이다.** 아래 항목은 시험 절차이며 실제 수행 결과는 VALIDATION.md와 검증 JSON에 따로 기록한다. 0.6.2 UI 보완 EditMode 194/194를 확인했고 릴리스 업데이트를 완료했다. 사용자가 지금 실물 시험을 할 수 없어 이번 UI의 아래 실물 항목·캡처는 NOT_RUN이다. 자동 시험을 실물 성공으로 대체하지 않는다.

현재 규칙은 [v5 독립 인식](PRODUCT-RECOGNITION-V5.md)과 [온라인 조회](ONLINE-LOOKUP.md), 결과 기록은 [VALIDATION.md](VALIDATION.md)를 따른다. 이전 평면 배치는 [v2 체크리스트](DEVICE-CHECKLIST-V2.md)에 보관한다.

## 준비 조건

- **실제 포장 AR 대상:** 테아닌과 밀크씨슬 활력솔루션, EAN-13 **8809375984692**, PT ID **18e83c5c-86a4-4e95-a131-411381789687**. `theanine-top`·`theanine-bottom` 두 크롭, 약 **58mm** 폭, 품질 평가 **95·100점**이다. 품질 점수는 기기 인식률이 아니다.
- 두 테아닌 크롭은 같은 상품의 공통 원점으로 연결하며 `developmentOnly=false`와 Physical Size를 확인한다. 원본/보정 사진·선택 영역·실측 또는 추정 여부·이미지 이름·라이브러리와 JSON 연결을 기록한다.
- **더단백 크런치바 초코 40g / 8801104671507:** 실제 바코드 식별과 영양·가격 표시 대상이다. 더단백 포장 앞면 AR을 구현·검증한 것으로 기록하지 않는다.
- `test-card`는 더단백 ID에 연결한 **개발용 브이젤 카드**다. 카드 위 정보판은 개발용 연결 시험이며 실제 더단백 포장 인식 성공과 구분한다.
- 소스 커밋·APK SHA-256·패키지·버전과 실행 씬 ProductAR를 확인한다. ImageTrackingProbe의 큐브 APK와 구분한다.
- 기기·OS·조명·거리·각도를 기록하고 명시적인 대상 기기에서 설치·실행한다. 서명 불일치를 정상 업데이트로 기록하지 않는다. 실행 캐시 files/il2cpp는 데이터 복원 대상에서 제외한다.
- 동시에 서로 다른 상품이 보이면 정보판을 숨긴다. 여러 상품의 정보판을 동시에 표시하는 시험으로 구성하지 않는다.

## 0.6.2 촬영 UI 캡처

`scripts/Build-Android.ps1 -Release`로 생성한 0.6.2 (9)를 동일 서명의 `-r`로 업데이트한다. 서명이 다르면 설치를 중단하고 사용자에게 데이터 삭제 여부를 확인한다. 아래 캡처는 `artifacts/ui-p0/`에 보존하고, 실제 수행 여부는 ui-p0 검증 JSON에 적는다. 이 표는 수행 전 절차다.

| 파일 | 조건 | 확인 |
|---|---|---|
| theanine-front.png | 테아닌 정면 | 앞면을 덮지 않는 정보판·선택된 크롭 윤곽·연결선 |
| theanine-tilt-30.png | 약 30° 기울임 | 상품과 함께 회전, 고정 15° 유지 |
| theanine-near-20cm.png | 약 20cm | 위치 정합·글자·윤곽 |

모든 캡처에서 Development Build 표시가 없는지 확인한다. 사용자 눈으로 확인한 이동·정합과 로그/한 프레임의 근거를 구분한다. 거리는 사용자가 잰 값인지 추정인지 기록하며 캡처만으로 실측 각도·거리나 숨김 지연을 단정하지 않는다. 대표 두 장은 WORKLOG에 연결한다. 미수행은 NOT_RUN으로 남긴다.

## 반복·부하 기록

아래 **최소 5회는 사용자가 수행할 테아닌 앞면 시험 양식**이다. 결과 칸은 비워 두며 미수행을 PASS로 채우지 않는다. 바코드를 먼저 읽지 않은 상태에서 시작해 앞면 AR을 독립적으로 확인한다.

시도마다 정면에서 첫 3D 표시 → 좌우 회전 → 거리 변경 → 완전 가림 → 재노출을 수행한다. 예시 범위는 회전 15~30도·거리 20/30/40cm이며 실제 조건과 실측/추정 여부를 기록한다. 상단·하단 크롭 전환과 탭 유지도 확인한다. 가능하면 영상 시각으로 첫 표시와 재획득 시간을 잰다.

실제 수행 횟수와 성공·실패·재획득 횟수를 함께 적는다. 5초 내 표시·잘못된 상품 표시 0회는 개발 확인 목표이며 공식 채점 기준이나 이미 달성한 성과가 아니다. 반복과 별도로 5분 연속 사용 시 크래시·리소스 누적·발열을 기록할 수 있다. 바코드 반복 시험과 개발용 카드 시험은 별도 표에 기록한다.

기존 센서 보완을 확인할 때는 AR 사용 중 등록·pause 해제·복귀 재등록 로그를 남긴다. 등록 성공만으로 정확한 센서 주기나 앱 성능 향상을 주장하지 않는다.
