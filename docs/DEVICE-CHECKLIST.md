# 실물 검증을 완성하는 절차

**현재 v3 자동 추종 시험은 [바코드 자동 정보창](BARCODE-FOLLOW.md)의 완료 기준을 따른다.** 아래 평면 탐색·터치 배치·앵커 시험은 이전 v2용이다. 새 기본 흐름에서는 바코드 인식 후 터치하지 않고 정보창이 나타나는지, 상품 이동·가림·화면 이탈·다른 번호·Home 복귀에 따라 위치와 표시가 올바르게 변하는지 확인한다.

기획·단계 목표는 [MILESTONES.md](MILESTONES.md), 실제 실행 결과는 [VALIDATION.md](VALIDATION.md)를 따른다. 이 문서는 아직 확인하지 못한 실물 시험을 재현하기 위한 절차다.

## 준비

1. ARCore 지원 Android 기기에 Google Play Services for AR을 준비한다.
2. 기기를 USB 연결하고 USB 디버깅을 승인한다. 개발 PC에서 `adb devices -l`로 명시적인 대상 serial을 확인한다.
3. `Builds/Android/ProductAR.apk`가 준비돼 있으면 `scripts/Install-Android.ps1 -DeviceSerial <serial> -Launch`로 설치한다. 기존 설치가 있으면 서명·버전을 확인한 호환 `-r` 업데이트를 사용한다. 삭제·데이터 초기화는 수행하지 않는다.
4. 앱 이름은 **상품정보 AR**이다. 설치 스크립트는 카메라 권한을 ADB로 부여한다. 사용자가 직접 설치할 때에는 앱의 카메라 권한 요청에 응답한다.

## 제품을 보여주는 시험

- 대상은 빙그레 **더단백 크런치바 초코 40g**, 실물 바코드 문자열 `8801104671507`이다.
- 바코드 전체와 양쪽 흰 여백이 보이도록 비추고, 초점이 맞을 때까지 잠시 멈춘다. 같은 번호가 서로 다른 카메라 프레임에서 3회 연속 확인돼야 결과를 확정한다.
- 최신 APK는 지원 기기에서 판독용 CPU 영상을 최대 1920×1080으로 선택한다. 기기 로그의 `CPU image source`와 `decoder` 크기를 확인한다.
- 제품이 확인되면 스캔이 중지되고 책상 표면 탐색 안내로 바뀌는지 확인한다.
- 미등록 안내가 나오면 표시된 **읽은 번호**를 실물 아래의 숫자와 비교한다. 다르면 오인식으로 기록하며 시연 매핑을 임의로 바꾸지 않는다.
- 15초 안에 판독하지 못하면 다시 스캔을 누른다. 조명·반사·거리·각도를 기록한다.
- 10회 반복해 값·형식·걸린 시간·실패 이유를 기록한다. 합성 바코드 자동 시험은 이 실물 시험을 대체하지 않는다.

## 현실 공간 배치 시험

상품 요약에 **빙그레 · 40g 1개 / 더단백 크런치바 초코**가 표시되면 상품 조회까지 끝난 상태다. 이 요약은 화면 UI이며 아직 현실 공간에 배치된 정보판은 아니다. 여기서 다시 스캔을 누를 필요는 없다.

화면 안내에 따라 진행한다.

- **책상 표면을 천천히 비춰주세요:** 바코드에서 카메라를 떼고, 책상과 주변 물체가 함께 보이도록 천천히 좌우로 움직인다.
- **상품 옆을 눌러 배치하세요:** 초록색으로 표시된 책상 영역에서 상단/하단 UI와 겹치지 않는 곳을 한 번 누른다.
- **정보판을 공간에 배치했습니다:** 가격·영양정보판이 나타나면 휴대폰을 좌우로 움직인다. 같은 책상 위치에 남는지 확인한다.
- **공간 추적을 복구하고 있습니다:** 빛 부족·특징 부족·과도한 움직임에 따른 안내를 따른다. 배치 전에도 이 안내가 나오며, 상품명 표시만으로 공간 추적 성공을 판정하지 않는다.

1. 제품 옆의 무늬가 있는 평평한 책상을 천천히 여러 각도에서 비춘다. 매끈한 흰 면·강한 반사·어두운 환경에서는 평면 탐색이 어려울 수 있다.
2. 표면 표시와 배치 안내가 나오면 제품 옆 표면을 누른다. 화면 버튼을 눌렀을 때 공간 객체가 생기면 실패다.
3. 정보판에 상품명·40g 규격·관측 가격 1,400원·2026-05-08 날짜·40g 기준 영양정보가 보이는지 확인한다. 1,400원을 현재가로 설명하지 않는다.
4. 휴대폰을 좌우로 움직이고 각도를 바꾼다. 정보판이 화면에 붙어서 움직이는지, 현실 위치에 남는지 구분한다.
5. 재배치로 같은 정보판의 위치를 바꾸고, 삭제로 사라지는지 확인한다. 다시 스캔은 이전 상품·정보판을 정리해야 한다.
6. 추적이 끊겼을 때 잘못된 위치의 정보판을 표시하지 않는지 확인한다. 앱을 백그라운드로 보냈다 돌아오면 다시 배치한다.

개발 검증에서는 `adb -s <serial> shell dumpsys sensorservice`와 해당 앱 PID의 로그를 함께 남긴다. AR 실행 중 `Motion sampling request 100 Hz; both sensors registered=True`, 앱 pause 시 `Motion sampling stopped`, 복귀 시 재등록을 확인한다. 센서 서비스의 추가 10000µs 요청도 함께 확인해야 하며 등록 성공 로그만으로 실제 센서 주기를 보장하지 않는다. 55초 비교용 프로브는 최종 앱에 포함하지 않는다.

## 재빌드

Unity에서 `Assets/Scenes/ProductAR.unity`를 연다. 씬을 다시 구성해야 할 때는 **Product AR → Prepare Project and Scene**을 사용한다. 이 명령은 생성 씬·프리팹을 다시 만든다.

한글 프로젝트 경로에서 Android 도구가 빌드를 거부하므로 `scripts/Build-Android.ps1`을 사용한다. 원본을 옮기지 않고 영문 임시 복사본에서 빌드해 APK를 원래 프로젝트의 `Builds/Android`로 가져온다. 생성한 임시 복사본의 경로는 빌드 요약에 기록한다.
