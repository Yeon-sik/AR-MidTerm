# 가상현실 중간 프로젝트

**사전 등록 앞면 AR은 테아닌 1종, 검증된 PT 바코드 연결은 더단백·테아닌 2종이다.** 바코드는 PT→OFF 순서로 범용 조회한다. 0.7.0 후보에는 식별한 상품의 앞면을 이번 실행 동안 등록하는 기능을 추가했다. 앞면 이미지와 바코드는 독립적으로 동작하며 앞면은 3D, 바코드는 2D 정보판이다. 같은 상품은 3D를 우선하고, 서로 다른 상품이 동시에 보이면 숨긴다. 여러 상품의 정보판을 동시에 표시하지 않는다. 기반 구조는 [v5 상품 인식](docs/PRODUCT-RECOGNITION-V5.md)을 따른다.

테아닌 밀크씨슬 박스는 사용자 제공 바코드 `8809375984692`·약 58mm 폭과 상단·하단 크롭을 등록했다. 2026-10-27 사용자 동일 상품 확인 후 PT ID `18e83c5c-86a4-4e95-a131-411381789687`로 연결하고 13,210원 관측 2건의 출처·신뢰도를 보존했다. 공개 영양 결과는 없어 비워 둔다. 브이젤 카드와 더단백의 개발용 연결은 계속 구분 표시한다.

현재 개발 기준은 **feat/ui-p0-video의 0.7.0 후보**다. OFF 영양정보와 출처·기준량을 추가하고 게시 가격을 제외한다. 포장 표기 주석은 보류하여 앱에서 숨긴다. 온라인 DTO를 로컬 Selected에 넣지 않고 실제 표시 상품과 키를 버튼·상품 변경 감지 기준으로 사용한다. 앞면 3D 우선·실패 프레임 즉시 해제·최대 0.65초 규칙은 유지한다. 자동 시험·릴리스 설치·실물 확인은 [검증 기록](docs/VALIDATION.md)에서 구분한다.

정보판은 상품 오른쪽 **12mm 간격·고정 15°**로 표시하고, 실제 추적 크롭 윤곽·연결선을 함께 숨기고 표시한다. 화면 경계에 따라 다른 변으로 옮기지 않는다. 테아닌은 가격 탭으로 시작하며 재스캔은 하단 바 하나다. [0.6.2](docs/validation/ui-p0-2026-10-27.json)·[0.6.1](docs/validation/online-lookup-finish-2026-10-27.json)·[0.6.0](docs/validation/barcode-online-lookup-2026-10-27.json)은 이전 버전의 증거다.

OFF 영양은 판매 상태의 100g/100ml 표준값과 Open Food Facts 출처를 표시하며, 자료가 없는 값은 만들지 않는다. 가격이 없으면 가격 정보 없음으로 표시한다. PT 공개 v1의 가격은 현재 게시가만 제공하므로, 앱에 표시되는 두 시연 상품의 관측가는 출처·날짜를 보존한 로컬 스냅샷이다. 추가 상품 3~5종은 정확한 바코드와 자료 확인이 남아 있다. 현장 앞면 등록 C는 A25 시험 앱에서 진라면의 등록→최초 인식→소실→재인식을 로그와 사용자 확인으로 검증했다. 정식 0.7.0 (15)에서도 진라면 정보판·윤곽·연결선을 갤러리 사진으로, 완전 가림·복구를 사용자와 로그로 확인했다. **C 기본 실물 흐름을 22시 전에 확인하여 제출 후보에 유지한다.** 반복 안정성·완전 종료 후 등록 해제·최종 빌드 회귀는 별도 확인한다.

상품마다 추가 마커를 붙이지 않는 확장은 [바코드 마커 기술 조사 보고서](docs/BARCODE-MARKER-RESEARCH.md)에 정리했다. ZXing·OpenCV 등 공개 구현, 2D 검출과 3D 자세 추정의 차이, 과제 적합성과 후속 검증 범위를 비교한다.

0.7.0 (15)는 A25 갤러리 사진으로 진라면 현장 등록 후 3D 정보판·윤곽·연결선 표시를 확인했다. 추적 소실·재획득 경로 전환은 로그로 확인했다. 추가 사진으로 모든 상품·출처 문구가 읽히는 것과 사용자 가림·복구를 확인했다. 카드 배경 오른쪽·윤곽 일부가 화면 끝에 걸려 최종 영상은 더 넓게 촬영한다. [실제 확인 범위](docs/validation/runtime-registration-retry-2026-10-28.json)를 따른다.

PT 공개 바코드 함수 → `not_linked`일 때만 Open Food Facts v3를 조회하는 계층을 구현했다. 현재 범위는 [0.7.0 온라인 조회와 검증 경계](docs/ONLINE-LOOKUP-0.7.0.md)를 따른다. [이전 설정·조회 기록](docs/ONLINE-LOOKUP.md), [도입 조사 정정](docs/BARCODE-PRODUCT-LOOKUP-RESEARCH.md)은 이력으로 보존한다. 설정이 없으면 로컬 전용, PT 오류면 확인 불가와 날짜가 있는 스냅샷을 표시한다. **2026-10-27 A25에서 두 시연 바코드의 PT 등록 표시·테아닌 앞면 3D·오프라인 대체 표시를 사용자와 확인했다.** 작업 초반의 404/PGRST202는 이후 200/matched로 바뀌었다. 정상 OFF 분기와 반복·부하 시험의 수행 여부는 검증 기록을 따른다.

바코드로 상품을 식별하고 사전 등록 이미지로 3D 위치를 추적하는 Android AR 카메라 앱이다.

강의 원문과 방향 선택 근거는 [강의 검토·완성 계획](docs/COURSE-ALIGNED-PLAN.md)에 정리했다. 현재 진행 상태는 [마일스톤](docs/MILESTONES.md), 이번 변경 묶음은 [작업 기록](docs/WORKLOG.md)을 따른다. 이전 v3의 2D 바코드 추종은 [기존 흐름](docs/BARCODE-FOLLOW.md), v2의 평면 배치는 [기존 마일스톤](docs/MILESTONES-V2.md)에 보관한다.

## 사용 흐름

- **앞면 경로:** 등록된 테아닌 포장의 두 크롭 중 하나를 FULL_TRACKING하면 오른쪽 3D 정보판과 크롭 윤곽을 표시한다. 영양이 없는 테아닌은 가격이 기본이며 영양 탭은 비활성이다. 더단백 포장 앞면 AR은 현재 시연 대상에 포함하지 않는다.
- **바코드 경로:** EAN-13을 3회 확인하면 독립적인 2D 정보판과 앞면 등록 여부 배지를 표시한다. 이미지가 없어도 사용할 수 있다.
- **현장 등록 경로:** PT 또는 OFF로 식별한 상품에서 `앞면 등록`을 누르고 포장 앞면을 촬영한다. 품질 검증에 통과하면 동일 실행 안에서 앞면만으로 3D 정보판을 표시한다. 등록 대상·출처를 촬영 시작 시 고정하며 앱 종료 시 사라진다. 실측 크기가 없어 ARCore 추정 크기를 사용한다. 영양·가격이 없는 상품은 누락 상태를 그대로 표시한다.
- 같은 상품의 복수 앞면은 허용한다. 다른 상품의 앞면이 동시에 보이거나 서로 다른 앞면/확정 바코드가 충돌하면 숨긴다.
- 미등록 번호는 읽은 번호와 **로컬 카탈로그 스냅샷 날짜**를 표시한다. 운영 PriceTrace 전체의 미등록을 단정하지 않는다.
- 소실·제한·LAST_KNOWN_POSE·pause에서는 잘못된 공간 표시를 숨긴다. 재획득·같은 상품 크롭 전환은 탭을 유지하고 다른 상품·재스캔은 초기화한다.

## 이전 구현·기기 검증 기록

다음 항목은 v3·v2 당시의 성과다. 현재 이미지 정보판의 코드 검증과 실물 성공을 구분한다. 전체 이력은 [구현·검증 기록](docs/VALIDATION.md)을 따른다.

- 바코드 판독, 정확한 로컬 매핑, 한국어 정보창, 자동 표시·선택 번호 추종·소실 시 숨김·다른 상품 스캔을 구현했다.
- Unity EditMode 자동 시험 **42/42 통과**. 회전 입력의 위치 좌표·화면 변환·잘림·오래된 결과·다른 상품 거부·추종 중지와 재시작, 영양성분표·가격의 값·단위·누락값을 포함한다. 기존 기기 시험은 이전 평면 배치 빌드의 기록이다.
- 카메라 UI를 스캔·추종 2단계로 구성했다. 상품 확인 후 재배치·삭제 없이 자동 표시하며, 위치 준비·소실·권한 오류를 구분한다.
- 영양정보를 기준량·열량과 성분별 함량이 정렬된 표로 표시한다. 관측 가격은 금액을 강조하고 판매처·관측일·개당 기준을 분리한다. 누락값과 0을 구분한다.
- Galaxy A25 / Android 16에 설치·실행하고 카메라 영상, 실제 1920×1080 CPU 이미지 입력, 합성 EAN-13의 Android 디코더 자체 점검을 확인했다.
- 2026-10-24 센서 요청 보완 후 실제 수평 평면 감지·터치 앵커 생성·정보판 배치를 로그와 사용자 화면으로 확인했고, 사용자가 휴대폰 이동 중 같은 책상 위치에 유지됨을 확인했다. AR 사용 중 100Hz 센서 요청을 유지하고 pause/복귀 시 해제·재등록한다. **10회 반복·장시간 검증은 미완료**다.
- 단발성 판독으로 미등록 안내가 확정되던 문제를 수정했다. 같은 번호를 3회 연속 확인하고, 미등록 시 읽은 번호를 표시한다. 반복 오독 재현 후 판독 영상을 640×480에서 1920×1080으로 높였다. 실제 입력은 [해상도 분석 기록](docs/BARCODE-RESOLUTION.md)을 따른다. 2026-10-24 사용자가 수정 앱의 실물 스캔 후 정확한 상품명 표시를 확인했다. 10회 반복 시험과 현실 공간 배치는 별도 검증한다.
- 바코드 연결은 사용자 제공 근거의 **demo-only** 매핑이다. 운영 DB의 기존 매핑은 미검증이다.
- 이미지 품질은 새 M0의 통과 조건이 아니다. 과거 시험은 [구기획 검증 기록](docs/M0-M3-validation.md)에 보존한다.

## 빌드·설치·남은 검증

현재 빌드 목표는 **0.7.0 (15)**이다. Android 버전·권한은 ProjectBuilder 빌드 경로에서 설정한다. 버전별 A25 업데이트·설치 해시·확인/미수행 항목은 [검증 기록](docs/VALIDATION.md)을 따른다. 기능 검증은 `scripts/Test-EditMode.ps1`, 씬·프리팹 갱신은 Unity 메뉴 **Product AR → Prepare Image Tracking Scene (No Build)**를 사용한다.

2026-10-28 소스 `ab7687e`의 전체 시험은 **378/378 통과**했다. 기존 378개를 유지했다. 0.7.0 (15) 릴리스를 A25에 같은 서명으로 `-r` 업데이트했고 설치 APK 해시 일치를 확인했다. 앞선 14번 빌드는 진라면 이미지 등록·상품 연결 뒤 실물 인식 실패가 보고됐다. 원인을 확정하지 않고 추적 단계 진단과 평평한 포장 안내를 보강했다. [재시험 검증 JSON](docs/validation/runtime-registration-retry-2026-10-28.json)에 해시와 실제 확인 범위를 기록한다. 이전 `aa40bc0`의 0.7.0 (13)은 C 없는 미설치 빌드이며, `3313647`의 **0.7.0-probe.2 (13)**는 등록·재인식 가능성을 확인한 개발용 앱이다. [시험 앱 기록](docs/validation/runtime-registration-probe-2026-10-28.json)과 제출용 릴리스의 확인 결과를 섞지 않는다.

- APK: `Builds/Android/ProductAR.apk` (생성 파일, Git 제외), 앱 이름 **상품정보 AR**, 패키지 `com.yeonsik.midtermar`.
- 영상용 릴리스: `scripts/Build-Android.ps1 -Release`. BuildOptions.None으로 개발 워터마크·DEVELOPMENT_BUILD 전용 코드 없이 만든다. 온라인 설정은 씬의 TextAsset 참조로 포함한다.
- 개발 빌드: `scripts/Build-Android.ps1`. 기존 개발 진단 경로를 유지한다. 두 경로 모두 한글 경로 제한을 피하도록 영문 임시 복사본에서 빌드한다.
- 현장 등록 검증용: `scripts/Build-Android.ps1 -RegistrationProbe`. 별도 `RegistrationProbe.apk`이며 Development Build다. 정식 영상·제출에는 사용하지 않는다.
- 공개 조회 자료 확인: `scripts/Test-ProductLookup.ps1 -Barcodes '<EAN-13>'`. PT 서버 자료·로컬 스냅샷·OFF를 구분하며 바코드를 등록하거나 원격 자료를 수정하지 않는다.
- 설치·실행: `scripts/Install-Android.ps1 -DeviceSerial <serial> -Launch`. 서명·버전을 확인한 `-r` 업데이트를 사용한다.
- 씬·프리팹 재생성: Unity 메뉴 **Product AR → Prepare Project and Scene**. 생성 씬을 수동 수정했다면 재생성 전 내용을 보존한다.
- 남은 실물 시험: [현재 이미지 정보판 체크리스트](docs/DEVICE-CHECKLIST.md). 포장 앞면 추적·회전·거리 변화·소실·재획득과 탭 터치를 확인해야 한다. 평면 배치는 [v2 체크리스트](docs/DEVICE-CHECKLIST-V2.md)에 보관한다.
